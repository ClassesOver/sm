# 按人工审阅判定告警，而非追求清零

依据是用户提供的逐句批注 Word（79 条批注、37 处建议表述）、指标用途 Excel 和完整产物附件。示例金额不是核准事实，示例中的留空不是可以自动补造的数据。用户后续确认的指标定义及用途优先于旧定义；历史冻结来源不自动套用新定义。署名保持现状，章节数按内容需要决定。

`scope_unknown` 既可能是旧事实没有登记信息，也可能是检查器尚不支持对应陈述。它不能通过默认“全院”消除。若事实中已有唯一、受信范围而检查器没有读取，才是可修复的误报。`statement_not_supported` 同样是当前证明不足，不直接等同于事实反证。

## Harness 应怎样判定正确

1. **给每个基准样本登记审阅编号和预期。** 不支持的断言、合法表述、待核实证据分别保存。R009/R070 区分预算时间属性；R014/R068 区分零与缺失；R030 区分开单和现金；R049 区分规模和风险；R052/R055 区分收入成本匹配；R058/R061 区分工作量和效率。指标选取另按 Excel 的 24 项、5 类用途以及 code/fieldRef 验证，不能凭同名选择。
2. **每个问题同时测正反例。** 如“执行率 80%，超预算”应报，“执行率 80%，低于预算”不应报；“月度事实＋月标签”应通过，“日度事实＋月标签”保持未知。还有凭证待核与已确认、完整总体与 Top-N 前缀、收入分析与预算分析的用途对照。缺证据的样本不能混入明确错误样本。
3. **做单因素变异。** 改金额、符号、单位、月份、科室、分母、事实指针或用途，检查相应诊断是否出现；恢复后重新验证。增加无关否定句、代码示例、重复标记等，验证不会误消警或误报。删除限定语后应重新暴露原先受限的经营断言。
4. **分层复跑。** 底层数值及身份；规划/用途/公式和期间；正文、图表、表格共同事实；实际编辑和 PDF/Word 产物。模型成稿另设留出样本，由业务审阅裁定，不由同一个模型自评后直接盖章。未运行、跳过、空样本及缺失评估必须明确记录。
5. **评价误报和漏报。** 报告 TP/FP/FN、precision、recall、已评估覆盖及 unknown 原因。不得把零输出当高准确率，也不能把未知项排除后声称整份报告通过。所有未知必须有原因及对应补证/实现动作。

业务信息不充分时，harness 最多可以判断“正确地保留了未知”，不能替代医院对预算版本、组织映射、收入归属、成本分摊和异常凭证的确认。79 条意见已映射不等于 79 条意见均已实现自动判定。

## 本轮已实现的基准与修复

运行：

```bash
MPLCONFIGDIR=/tmp/os-replay-mpl .venv/bin/python -m scripts.check_professional_review \
  --output /tmp/professional-review-harness.json
```

新增 27 个合成业务政策样本，对应 Word 中 11 个审阅编号，保存文档哈希、样本身份、预期诊断及结果；不是全部 79 条意见的自动验收，也不是业务盲评。输出逐样本 FP/FN、版本及样本哈希，非空唯一样本校验防止漏执行；预期会告警的样本在检查器完全静默时必须失败。

基准先复现 3 个漏报：一句中“预算版本无法确认”的无关限制抑制了后面开单收入推断现金、相关性推断效率、规模推断管理异常的诊断。现在仅检查对应推断及其直接支配的否定表达，额外回归“不能仅凭／无法通过／不应根据……”的合法限定。专业规则升为 professionalReview/2，进入既有质量身份，不改变发布下载策略。

27 个有限基准修复后 FP=0、FN=0，只说明此已知集合通过；真实附件本来没有命中这些有限专业模式，仍需针对当前 unknown 的结构化证据检查，不能拿这组成绩宣称业务验收完成。

验证：专业基准、原专业复核及表格/质量缓存回归 178 passed；工作流质量、纠错预算及全部 8 条发布/导出非阻断契约展开 110 passed。两个核心模块 mypy、三个 Python 文件 Ruff 和 diff 检查通过。附件质量回放仍为 197 个数值支持 unknown、16 对图表及依赖告警、5 个登记表告警和 1 个覆盖告警，未用关闭规则降低数量。

## 后续推进顺序

- 先把真实附件的 unknown 按“已确认误报、真实来源缺口、业务定义待确认、检查能力未覆盖”逐项建账；每条绑定定位、审阅编号、所需证据及责任环节。未核实前保留未裁定，不硬分成 bug 或业务错误。
- 从新计划入口完善已批准的用途、期间、范围、预算属性及可用公式。无授权不补全范围，不能用模板文字弥补事实缺项。
- 统一结构化表格和图表的来源投影，补注册而不造来源。先展示根因，再展开受影响的句子/表格/图表；汇总可以去重，原始诊断不可丢失。
- 根据 R003/R020/R057 的建议表述构造有同源事实的经营总览与结论矩阵，替代长章首句摘录；明确累计、同期、预算分母及缺项。避免为了核心结论页而重新引入未经证明的摘要。
- 持续加入业务人员裁定的留出样本。模型和规则修改都比较误报、漏报及证据覆盖，改善必须在同一冻结输入上可重现。

上述后续项是实施方向，本轮没有宣称全部完成。业务语义告警继续为软告警，可读且身份核验通过的 PDF/Word 继续交付，失败原因保留。
