# 编辑器业务知识来源附录：分层技术证据

本增量把现有Editor同一次授权复核得到的原文摘录带入PDF/Word，显示精确修订、用途、原件定位、请求期间、登记/事件时间和当前解释支持状态。原文可访问不等于解释获支持；失效材料不携带旧标题/摘录。

## 证据层级

1. 新Editor投影反例从实际冻结事实/semantic receipt及trace.validate进入原有附录构建器，注入当前授权候选映射，覆盖有效、撤回、外部basis、quote变化及无fact的纯文字引用；没有把模拟撤回称为真实管理服务撤销。
2. 实际WeasyPrint/pandoc读取手工构造的严格知识展示载荷，生成原生PDF/Word；读取真实成品文本和Word样式/分页，调用PDF成品可见性验收。这里证明格式投影，不冒充首次公开报告或实际数据库知识检索的连续导出。
3. HTTP故障注入复用真实WorkspaceReportService/Editor渲染、产物持久化及ASGI下载，投影函数恰好失败一次，验收失败原因保留，实际PDF/Word仍可下载且size/SHA/文件头一致。仓储为隔离内存端口，不是PG。

## 验证

- 首批产品红例4failed（缺少知识投影），修复后4passed。
- 独立审查发现成品知识可见性漏检和Word标题分页遗漏；三条可见性红例均DID NOT RAISE，修复后相关集合86passed/30.24秒。
- 纯文字及整体16KiB预算2passed/9.64秒；最终混合/单独来源开关和两种HTTP精确故障6passed/56.24秒；实际PDF/Word再读成品可见性1passed/26.70秒。
- AGENTS指定非阻断节点76passed/1skipped/57.75秒。集合重叠，不累计为独立总数；未重复完整项目测试。静态检查通过，弃用警告保留。
- 原始日志无损gzip保存。运行`python verify.py`可离线核对文件清单、渲染身份、实际两格式文本及Word附录样式/分页和日志。
