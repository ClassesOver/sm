# 首次文档与新计算修订的知识来源交付证据

本增量把同一次身份和当前授权复核得到的解释支持状态、知识原文摘要带入首次 PDF/Word 装配交付分支及新计算修订。附录显示精确材料版本、用途、原件定位、请求期间、登记时间、事件时间和当前支持状态；原文可访问不等于解释获支持。

知识载荷成功时默认展示来源，保留已有显式来源关闭设置。附录投影或 16 KiB 总预算失败时，保留已核验的解释状态，丢弃旧来源摘要，明确返回 issue，继续签发实际 PDF/Word。首次输出目录、发布返回值和在线来源链接使用清单的精确修订号，不重复递增装配后的修订。

## 连续链路和证据范围

- 五组用例使用随机专用 PostgreSQL/pgvector 容器中的管理登记、审核、知识发布及授权读取；合成原件字节通过管理服务 `read_original` 读取后归档，同时保存 `get_document` 返回的原件 hash、解析回执、审核状态和登记时间。
- 早期材料 `known-context` 可用于报告，晚于历史知识截止的 `later-context` 虽登记但不能进入模型候选、附录或下载文件。每组保留原件、冻结依据、知识引用、实际追溯索引及清单、登记事实、PDF/Word 和真实 HTTP 下载的相同字节。
- `cases/known-initial` 与 `cases/known-initial-knowledge-fault` 是最后目录修订修复后的重验结果，另保存这两组索引登记的全部五个输入文件。其余三组保留先前连续运行的登记事实文件及正文；未归档其余所有注册输入，不能把该部分称为完整可重算备份。
- 两个正常分支验证附录精确版本、摘录、原件坐标和实际 PDF 注释／Word 超链接。两个知识投影故障及一个解释支持整体故障均明确验收失败，实际双格式仍经签发和 HTTP 字节身份核对。
- 五组均进入真实 Editor 服务和浏览器，核对来源原文、键盘展开／收起、只读无报告写入，以及 1440、1280、768、390 四宽度。各组 axe 严重／关键问题为零；这些检查不证明整个产品全部页面或资源预算已验收。

首次分支借用已有口径采用 fixture 准备登记分析，实际文档生成、装配、渲染和发布调用 `execution=None` 分支；它不是从全新用户报告请求开始的完整业务工作流。查询端口由合成 DuckDB 接管，段落模型受控，向量为固定八维协议向量；成品保留适配器的 StarRocks 方法名不代表本轮连接真实 StarRocks，也不代表中文召回或业务负责人批准。

## 验证记录

- 新投影单元红例五项失败；原有文档集成暴露遗漏知识附录和首次修订重复递增。夹具原硬编码 XLSX、渲染前公开地址未配置等装配问题另计，不当作产品能力证据。
- 相关来源与非阻断集合 **130 passed / 2 deselected / 65.14 秒**；正式指标和登记支持共享回归 **31 passed / 36.21 秒**。
- 连续正常／故障五节点 **5 passed / 231.86 秒**，专用容器清理成功；此后发现输出目录还多加一次修订号。
- 输出目录独立红例为 `assert 2 == 1`；修正后定点非阻断和发布回归 **20 passed / 11.42 秒**，首次正常及知识故障 HTTP 两节点 **2 passed / 99.10 秒**，清理成功。
- 测试集合重叠，不累计为独立通过数；未重复完整项目测试。九个受影响 Python 文件语法、JS 语法和差异检查通过；相对基线没有新增 Ruff 诊断，九条既存诊断保留。
- 首轮浏览器曾在业务 API 请求前动态模块加载失败；保留启动 JSON／PNG 诊断，独立 Vite 模块和页面探针后连续运行恢复。没有以跳过浏览器断言替代修复或宣称长期缓存问题已解决。磁盘不足导致的一次隔离库启动失败也单独留档；只清理可重建 Docker 构建缓存，没有删除业务数据。

原始日志和完整登记输入无损 gzip 保存，保留原 CSV 的 CRLF 字节。运行 `python verify.py` 可离线核对完整文件清单、原件登记 hash、已归档注册输入、下载字节身份、实际文档文字／Word 样式、精确修订链接和日志。`run-semantic-evidence-tests.py` 仅创建／销毁随机专用测试容器，禁止将其测试数据库参数指向业务库。
