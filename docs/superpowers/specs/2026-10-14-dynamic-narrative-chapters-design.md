# 动态叙事章节设计

## 目标

让报告章节由本轮已经验证的管理发现、影响和证据动态决定。收入、工作量、预算、全成本、费控和资金只作为数据领域与指标来源，不作为固定目录。

## 当前工作流评估

现有 Reporting 流程已经具备动态提纲能力，但动态边界停留在 `analysisId` 分组：

```text
需求规范化 → 数据确认 → 数据画像 → 指标语义 → 分析计划
→ 取数与数据集 → 详细分析计划 → 生成提纲
→ 分析/补证/图表/章节成稿 → 汇编与发布
```

`generate-outline` 在 `run_reporting_analysis` 之前执行。提纲模型只能返回章节标题和 `analysisIds`，因此章节规划看不到本轮真实异常、归因闭合状态、影响金额和证据等级。分析计划又要求每个分析项回答一个原子问题，原子项增多后，章节数量容易随分析项数量线性增长。

现有的取数、事实快照、补证、引用、图表、编辑器追溯和发布门禁都是可复用的基础设施。本设计只改变“分析结果如何组织成章节”，不改变事实身份、来源校验和非阻断发布契约。

## 设计

### 分离分析执行与叙事编排

分析计划继续负责原子事实：规模、趋势、异常、贡献、比较和限制。分析阶段完成后，服务端从确定性事实和补充 evidence 投影管理发现；只有管理发现生成后，才生成面向读者的最终章节。

目标流程：

```text
原子分析任务
→ 固定 facts 与补证 evidence
→ 管理发现图谱
→ 动态叙事提纲
→ 章节图表与正文
→ 汇编、校验、发布
```

为了兼容现有分析子流程，可以在过渡期保留一个内部的分析执行分区。该分区只服务于分析任务调度，不出现在封面、目录、章节标题或用户可见追溯树中。

### 管理发现

`FindingCard` 是服务端可校验的管理发现，不允许模型自由创建事实。每个发现必须绑定：

- 稳定 `findingId`；
- 一个或多个原子 `analysisId`；
- 发现类型：规模、趋势、异常、归因、经营影响、数据限制；
- 指标、期间、组织粒度和币种；
- 影响值及单位（可为空）；
- 证据等级：直接分解、规则判断、统计关系、业务假设、证据缺失；
- 优先级、可行动性、引用和限制；
- 与其他发现的关系。

发现的数值、期间、单位、贡献和引用只能来自冻结事实。模型可以生成业务标题和解释，但不能计算或补写发现数值。

### 动态章节

最终章节按发现关系聚类，而不是按领域或分析项一对一生成。聚类信号包括：

- 是否回答同一个管理问题；
- 指标、期间和组织粒度是否一致；
- 是否共享驱动因素或管理动作；
- 是否存在已验证的跨域关系，例如工作量与收入、收入与成本、收入与资金；
- 合并后是否仍在章节输入和版面预算内。

章节规划输出发现集合、关联分析项、动态标题、章节目标、优先级和编排理由。`analysisIds` 继续保留用于血缘兼容，但 `findingIds` 是章节内容的主要边界。

章节类型只用于渲染行为，例如主发现、附录或限制说明；不要求所有报告都出现同样的章节类型。没有可靠数据的领域不生成空章，低影响发现可以合并或进入附录并记录去向。

### 服务端裁决

模型提出章节候选后，服务端必须验证：

- 高优先级发现恰好覆盖一次；
- 低优先级发现有正文、附录或明确忽略理由；
- 章节至少包含一个真实发现；
- 不同期间、粒度或口径的发现不能合并；
- 同一事实不能在多个章节中重复作为独立结论；
- 章节标题和目标能概括其发现集合；
- 章节输入和图表数量不超过根据内容量计算的预算。

校验失败时只要求模型修正章节候选，不重新计算事实。连续失败仍保留已生成产物和具体质量告警，遵守项目的非阻断发布契约。

## 兼容与边界

- 保留现有 `ReportOutline`、`SectionWorkItem`、`Citation`、`AnalysisEvidence` 和报告编辑器追溯接口的兼容字段。
- `analysisId`、dataset 身份、引用、哈希和发布门禁仍由服务端签发。
- 不在本设计中引入因果推断、预测模型或自动改变指标口径。
- 相关性只能生成统计关系发现，不能升级为确定原因。
- 不以固定章节数量作为成功标准；章节数量由本轮发现数量、优先级、关系和内容预算共同决定，并受系统安全上限约束。

## 验收标准

1. 提纲能够使用真实分析结果中的异常、归因和证据等级。
2. 没有可靠数据的领域不会生成空章节。
3. 工作量与收入等共享管理问题的发现可以合并到一个章节。
4. 期间、粒度或口径不一致的发现不会被错误合并。
5. 每个重要发现可追溯到事实文件和引用；正文、图表和表格继续共享同一事实。
6. 报告章节数量不再随原子分析项数量线性增长。
7. 现有下载、编辑器导出和非阻断发布测试继续通过。
