## 1. 交付目标与边界

本计划交付一套完整的报告追溯功能。分批仅用于控制依赖、审阅和验证成本，不以内部试点决定是否继续实现核心能力。各批通过技术验收后推进下一批；未通过则修复并复测，不通过删除需求来宣称完成。

最终用户能够从报告中的指标、结构化表格单元格、分析结论和静态图表打开来源，查看具体事实、计算依据、实际作图数据，最终预览或按权限下载报告生成时的 CSV。保存、人工编辑、历史恢复、重新分析和 PDF/Word 导出之后，来源仍指向正确的数据版本，已失效内容有明确提示。

### 1.2 明确排除与能力限制

- Plotly、交互图表及图内数据点点击不实施；通过静态图下方的来源入口查看整图和作图表。
- 不开放任意 SQL、跨报告自由查询或任意字段聚合；下钻只使用本报告登记的快照与规则。
- CSV 是报告工作流生成或登记的输入快照，可能已经聚合，不等于业务源库的逐笔明细。缺失粒度不在历史报告查看时补查。
- 支持现有分析方法的证据记录与展示，不借此开发新的预测、回归或因果推断引擎。某类分析尚未产生，登记其暂不适用；已经产生的类型必须接入相应证据。
- 新生成的结构化表格纳入单元格绑定；任意人工新建表格、旧报告自由文本不自动猜测来源，允许清晰显示“未绑定”。
- 保存来源文件可支持核查，不自动等同于算法正确、完全可复算或业务因果成立。

### 1.3 完整交付的判定

“完整”指 F01～F12 的流程与状态均已实现。单个对象确实缺少数据时允许显示不可用；新报告在符合条件且输入完整时却系统性缺失 fact 或作图绑定，属于未完成或缺陷，不能靠降级绕过验收。旧报告兼容性和新报告覆盖率分别统计。

## 3. 统一追溯模型

### 3.1 三条业务链路

```text
正文/单元格 → claim / 对象绑定 → 具体 fact → 输入 facts → CSV 快照
静态基础图 → 实际作图数据 → 筛选/分组/换算等规则 → CSV 快照
静态分析图 → 实际作图数据 → 分析 facts / 计算记录 → 输入 CSV 快照
```

Citation 继续提供 dataset 级引用。它可以作为用户入口，但本身不能证明具体数字、单元格或 CSV 某一行参与了计算。分析依赖记录是数据关系，不作为可执行脚本表达式。

### 3.2 建议契约

以下为待实施契约，名称可遵循仓库既有命名统一；B0 冻结版本和字段。

| 对象 | 最小内容 | 核心约束 |
| --- | --- | --- |
| `RevisionTraceIndexV1` | reportId、revision、workflowRunId、正文身份、Profile 身份、来源记录和文件引用 | 被权威 manifest/context 登记；不以自身携带的 hash 作为唯一信任根 |
| `FileRefV1` | 资源 ID、服务端相对路径、媒体类型、size、sha256 | API 不返回工作区路径；只从当前 revision 的授权索引解析 |
| `DatasetSnapshotRefV1` | datasetId、FileRef、sourceType、requirementId、期间角色/窗口、rowCount、物化时间 | 数据库 CSV 和 URL CSV 区分；未知旧时间显示未知，不用 mtime 推断 |
| `FactRefV1` | analysisId、事实 FileRef、JSON Pointer | 不可变文件内精确定位；只能读取登记事实类型，限制指针长度和访问范围 |
| `ComputationRecordV1` | 方法/版本、参数、输入 CSV/factRefs、预处理、关键中间 FileRefs、脚本/执行身份、输出 facts、限制 | 输入输出齐全，无循环；运行成功不自动标记数值复核通过 |
| `ChartTraceV1` | chartId、图片 FileRef、plotDataRefs、datasetRefs、可选 factRefs、转换说明、系列/类别/单位映射、脚本身份 | 同一份最终作图数据生成图片并登记；区分观测、预测及区间 |
| `SubjectBindingV1` | 稳定 subjectId、类型、位置/结构定位、subjectSha256、claim/fact/chart 引用 | 不依赖易变字符偏移或最近数字；重复标记不能复制有效授权 |
| 表格单元格定位 | tableId、rowKey、columnKey、subjectId | rowKey 是冻结结构键；排序与值修改分开，插入行列不能复用旧单元格身份 |

优先使用“事实文件身份 + JSON Pointer”，不先建立全局事实数据库。JSON Pointer 只在同一个冻结文件身份下有效；新文件重排不静默迁移旧引用。派生事实引用具体输入记录，不能只用含义可能重复的 metricCode。

时间、Decimal、空值与数值精度采用统一 canonical 规则；禁止 NaN/Infinity 进入契约。现有 float facts 按既有精度冻结，核对使用指标明确的精度与容差，不通过换序列化格式伪造相同 hash。

### 3.3 状态独立建模

| 状态维度 | 建议值 | 用户语义 |
| --- | --- | --- |
| 内容绑定 | valid / stale / unbound | 当前正文/图片说明是否仍对应证据 |
| 文件可用性 | available / missing / expired / integrity_failed | 历史文件能否读取且与登记一致 |
| 计算验证 | verified / not_checked / failed / not_applicable | 是否按独立规则完成数值核对 |
| 证据性质 | observed / computed / estimated / interpretation | 观测值、计算值、估计值或业务解释 |
| 复算能力 | reproducible / limited / unavailable | 是否具备重现本次运算的输入、方法与环境 |

界面按上下文显示少量必要信息，不堆满状态标签。文件完整但正文改值：可看旧证据，提示当前内容待复核；文件完整但未对账：显示可追溯，不显示“数值已验证”；文件被篡改：拒绝受损文件内容读取，报告主编辑流程仍可使用。

### 3.4 生成与展示边界

- 来源身份和引用由服务端校验登记；模型可选择已提供的事实引用，不自由签发来源、hash、路径或权限。
- 展示业务名称、实际文件名、期间、范围、方法和必要限制。DatasetLineage、JSON Pointer、完整 hash 不放到默认业务界面。
- 查看、预览、下载和保存均不重新查询数据源或执行分析脚本。需要复算时作为独立受控验证执行，形成新记录，不覆盖旧事实。
- 语义缺失按仓库规则软告警；未知引用的授权访问、路径越界或文件完整性失败硬拒绝证据读取。软告警不能用来跳过新功能的验收门禁。

## 4. CSV、facts 和图表的功能细则

### 4.1 CSV 快照

1. 从当前 report/revision 的来源对象解析 CSV，展示实际文件名与业务标签。查询物化文件可能是 `dataset-…csv`；不得将效果图中的友好名称当成已有真实文件名。
2. 预览默认 50 条记录，最大 100 条/页；固定文件记录顺序，返回总行数、当前页、截断说明和签名游标。CSV 引号内换行按一条记录处理。
3. 建议初始上限：每页 50 列、单元格 4 KiB、响应 1 MiB；宽表提供受控列选择，长字段显示截断提示。字节超限可返回不足一页记录，不能伪造完整页。
4. 复用现有 CSV 解析器，不用字符串按逗号/换行拆分。既有输入单文件上限是 200 MiB，服务端校验和解析策略必须在 B0 压测确认，避免每翻页都全文件入内存。
5. 同一次受控文件读取中确保校验对象与解析对象一致；缓存按授权上下文与文件身份分区，不因相同文件名复用其他报告结果。
6. 不对预览默认求合计，不把所有行标记成“已用于该指标”。有明确记录选择规则时才定位相关行；大规模选择保存范围/条件及稳定记录定位，不必逐行写入巨大清单。
7. 提供下载能力：授权原文件下载返回快照原字节；脱敏/表格安全转换下载为独立派生产物，明确转换策略、来源和不同身份。脱敏文件不冒充原始 CSV。
8. 原始数据与可分享报告权限可能不同。B0 明确谁能预览哪些字段、谁能下载哪种文件；默认只展示配置允许字段，不把分享编辑链接自动升级为全部明细读取权限。

### 4.2 确定性 facts 与表格

- 基础事实展示原字段、范围、期间和聚合；比较事实同时展示本期/基期；比率展示分子分母；对账展示容差、差异及失败组摘要。
- 正文 claim 通过 factRefs 明确对应记录，校验 metric、期间、单位、范围和数值；用户看到的是生成时值与当前内容的关系。
- 服务端装配新结构化表格时冻结行列键及单元格绑定，不在最终 Markdown 中靠位置猜测。总计行、比例列和排名列分别绑定各自事实。
- 多来源事实逐一保留输入文件身份，不能只列出一个“代表 CSV”。
- 自然语言解释保留支持事实及限制；没有业务证据时不得把相关性或净增量贡献表述为已验证因果。

### 4.3 复杂 facts

完整支持“登记、定位、展开与核查”流程；对当前生产工作流输出类型建立清单：基础多步计算、贡献分解、相关性，以及实际存在的补充统计/预测/异常分析。通用计算记录承载脚本证据，方法专属字段通过明确契约补充。

必须保存：输入 CSV/facts；筛选、join、期间对齐、异常/缺失处理；方法和参数；必要依赖版本与种子；关键中间表；输出记录；运行身份、验证结果及适用限制。不是每个局部变量都必须落盘，但解释最终结果所需的中间值不能缺失。

示例：

```text
claim：A 院区占收入净增量的 66.7%
  → 派生 fact：400 ÷ 600 × 100%
    → A 增量：1600 - 1200 = 400
    → 全部院区增量：3600 - 3000 = 600
      → 本期 CSV、基期 CSV（固定范围和身份）
```

零净增量、正负抵消及负基数需要明确计算规则与限制。相关性记录变量、方法、样本数和数据对齐；预测记录训练/观测范围、预测范围、方法与不确定性。环境无法完整复算时显示能力限制，不能因保存了脚本就声称可重现。

### 4.4 静态图表

1. 在现有作图步骤中保存实际传给绘图库的最终数据，并以同一份数据生成 PNG/JPEG；禁止画完后另算来源表。
2. 作图数据独立于输入 CSV 登记；若与输入完全一致可直接引用，不能让新增追溯逻辑重复计算造成偏差。
3. 保存系列、类别、排序、单位、轴映射、Top N/其他项、缺值、换算及必要分面/区间信息。基础图直接追到 CSV；分析结果图追到具体 facts 或计算记录。
4. 图片身份、作图数据、脚本身份与输入来源联合发布。来源关系、数据对账、视觉表达分别验证：哈希不能证明柱高、轴范围或图例正确。
5. 保留既有视觉检查能力及其真实检查状态；未进行视觉检查不能显示“视觉已通过”。
6. 入口为图下“查看图表来源”，提供“作图数据 / 计算说明 / 来源 CSV”。不增加图内点选。

## 5. 接口、授权与资源边界

### 5.1 建议 API

统一前缀：`/reports/v1/editor/{report_id}/{revision}/api`。以下路由是设计建议，B0 与现有风格统一后冻结。资源 ID 是不透明引用，客户端不能提交 workspace、文件路径、SQL 或授权身份。

| 方法与相对路径 | 用途 | 输入/响应重点 |
| --- | --- | --- |
| `GET /sources` | 返回当前文档来源概览 | 分页和声明能力；只返回轻量对象信息 |
| `GET /sources/{subject_id}` | 正文、表格或图表入口 | 当前绑定、快照可用性、相关 fact/chart/dataset refs |
| `GET /facts/{fact_ref_id}` | 具体 fact 及一层输入关系 | 方法、结果、告警；依赖按需加载，不递归返回整个图 |
| `GET /charts/{chart_id}/source` | 图表来源 | 图表身份、作图数据和转换记录 |
| `GET /datasets/{dataset_ref_id}/preview` | 输入 CSV、作图表或中间表的只读预览 | 受控列选择、limit、签名 cursor；标注文件角色 |
| `GET /datasets/{dataset_ref_id}/download` | 获取授权原始 CSV | 会话和下载能力检查，附件响应，不返回服务器路径 |
| `POST /datasets/{dataset_ref_id}/exports` | 创建脱敏/安全转换导出 | 只接受已登记策略代码，返回 exportId |
| `GET /data-exports/{export_id}` | 查询派生导出状态 | 授权状态与完成下载入口；无长期公开文件链接 |
| `GET /data-exports/{export_id}/download` | 下载完成的派生文件 | 重验权限、源身份与任务归属，明确派生产物 |
| `POST /sources/validate` | 校验当前草稿中的绑定 | 草稿版本/摘要与受限内容，返回 subject 状态及校验基准 |
| `POST /sources/{subject_id}/drilldown` | 快照内单维度汇总 | 允许维度代码、limit、cursor；返回来源身份及对账信息 |

原始文件下载流式处理；派生导出复用现有任务模式实现限流、取消/失败与临时产物清理。状态读接口不触发计算。纯预览不需要创建新的报告 revision。

### 5.2 错误语义

| 情况 | 处理 |
| --- | --- |
| 合法对象，但正文已改或明细过期 | `200` 的可用元数据中携带状态与 warningCodes；依赖操作按明确业务错误处理 |
| 对象缺失或不属于当前授权索引 | `404`，不暴露其他报告对象是否存在 |
| 会话/能力不允许 | 沿用当前授权错误语义；不返回受保护元数据或字段 |
| 文件身份或 hash 不一致 | 完整性错误，拒绝文件内容；前端保留报告编辑能力 |
| 请求形状、维度、列选择或游标非法 | `4xx` 稳定错误码，不进入执行器 |
| 资源超限/并发饱和/超时 | 明确限额、稍后重试或缩小请求提示，不静默省略并冒充完整结果 |

建议稳定代码：`source_missing`、`subject_stale`、`fact_binding_unavailable`、`snapshot_expired`、`snapshot_integrity_failed`、`dataset_access_denied`、`cursor_invalid`、`drilldown_unavailable`、`resource_limit_exceeded`。具体 HTTP 映射在 B0 固定，预览和下载不得因错误正文泄露字段或路径。

### 5.3 统一实现要求

- 复用 `_read_context`、scope 恢复、同源/CSRF、资源登记和现有 workspace 路径检查。新增明细能力权限检查，尤其覆盖分享会话。
- 分页游标签名并绑定 report/revision、资源身份、选择条件、位置和过期时间；预览序号绑定原快照记录顺序，下钻序号绑定稳定分组顺序。
- API 使用 private/no-store；服务端缓存含授权上下文摘要与文件 hash，不能跨权限复用脱敏结果。
- facts 展开限制深度、节点数与响应字节；大结果分页。拒绝循环依赖和重复展开造成的无限遍历。
- 日志使用 loguru，记录请求编号、对象身份、耗时、错误与行数；不记录原始记录、敏感条件、授权 token 或完整 SQL。
- 下载文件名做安全处理；脱敏/表格安全转换保留转换说明，避免用户以为数值或字节与原 CSV 完全相同。

## 6. revision、草稿与保留生命周期

### 6.1 内容状态

- 新生成：正文、claims、facts、图片和作图数据完成绑定后发布来源索引。
- 未保存编辑：前端立即将受影响绑定标为正在校验/待复核；校验响应必须绑定请求对应的草稿版本，丢弃旧响应。
- 保存：按现有 CAS 保存；来源文件不改写，基于当前对象内容计算状态。不能因其他段落修改而让全文全部失效。
- 撤销：恢复到同一已登记对象的原规范化内容后可重新验证；无法确认对象身份则保留待复核。
- 表格排序：稳定行列键仍匹配时保持绑定；改值、插入、复制和合并单元格按身份规则重判。
- 图表：图片身份与图题/图注分别绑定；解释文字修改不使未变化 CSV 变成损坏，图片替换不能继续声称旧图来源有效。
- 历史恢复：恢复正文同时恢复/验证该历史版本的来源关联，不把最新事实套到旧正文上。

### 6.2 发布与导出

1. 初次发布前，校验 dataset/lineage/citation、facts、图表和来源索引，注册受信资源身份。
2. 保存草稿保持当前 revision；导出基于一次冻结的 Markdown 和来源状态生成 N+1。
3. N+1 未变化对象重绑定新 revision，可共享原不可变输入；变化对象保留待复核说明。新报告版本不意味着生成了新 CSV。
4. 使用暂存目录、文件验收和单一可见提交点，保证历史列表及来源 API 不读取半个 revision。与现有渲染原子移动、产物持久化及 context 提交协调，不假设多个系统天然事务一致。
5. 提交前失败仅清理本次操作拥有的暂存/未发布资源；提交后授权签发失败保留完整 revision，支持重试，不能删掉已提交版本。
6. 重新运行查询/分析产生新来源身份；旧 revision 索引保持不变，不按“latest workflow result”动态解析旧来源。

### 6.3 保留、恢复与兼容

- 来源文件默认至少保留到最后一个引用它的报告版本结束保留期；可从现有权威索引扫描有效引用，未达到规模需求前不强制新建引用计数数据库。
- 删除 revision 只移除其拥有的记录；共享 CSV、facts、作图数据和中间结果仍有引用时不删除。下载派生文件使用独立短保留期。
- 清理意外、工作区丢失或旧部署无文件时，元数据可读、明细明确不可用；不以实时重查填充历史。
- Host 工作区保留不等于已验证持久备份，B9 要验证进程重启、重新注册和部署恢复。
- 旧报告没有来源索引：正常编辑导出，显示无可用来源。只允许基于仍存在且可校验的权威产物进行显式迁移，不反推事实、行映射或公式。

3. 历史读取与恢复使用各自来源索引，重新分析产生新身份，不覆盖旧引用。
4. N+1 导出从同一内容快照生成正文、来源索引和文件；补齐 manifest 传递与提交边界。
5. 处理重复导出、旧版重定基、并发来源读取、失败清理、提交后授权失败恢复。
6. 接入共享源文件保留与删除，验证历史版本不受其他 revision 清理影响。

验证：修改数字/标签/期间/图注、无关段落修改、撤销恢复、复制/移动 marker、表格排序/插行/改值、AI 改写、双窗口 CAS、历史恢复、N+1、重新分析以及故障注入。

G6：所有内容变化准确更新对应来源状态；新旧版本不串数据；提交失败不暴露半个 revision；正式开启内部编辑追溯能力。

交付：内容校验与 revision 来源继承、恢复/清理逻辑、全生命周期测试记录。

### B7：快照内单维度下钻

实施：

1. 为每个已登记指标声明可用维度、算法和输入要求；生成规划期物化所需范围与投影。旧快照缺维度时返回不可用。
2. 复用受限计算能力，仅按服务端登记规则处理快照；强制范围不可被用户覆盖。
3. 覆盖可加金额、比率、平均值、去重与半可加指标的能力判定和正确执行。缺少必需输入时禁止执行，不能套用通用 sum。
4. 对可执行分组返回结果、原始范围、快照身份、计算说明和对账摘要；稳定排序和签名分页。
5. UI 仅展示可用维度，并说明不可用原因；维度切换不改变原报告值或生成新的“历史数据”。

聚合规则：金额在互斥完整分组中求和，含空值组；比率用总分子/总分母；平均值用合计/样本数；去重需要正确的标识或可合并状态，组人数之和不作为总体；时点余额限制可汇总维度。

验证：每类指标至少有一个正确输入例和一个拒绝例；空组、负数、重复键、缺字段、非法维度、跨对象游标、超时、当前源库变化不影响历史结果。对不可加指标采用其定义核对，不强求组值之和等于总值。

G7：能力判定和所有适用算法通过独立答案核对；没有输入的能力明确不可用；原快照范围不被扩大。

交付：下钻声明、服务、UI、算法与资源验证记录。

### B8：PDF/Word 来源编号与附录

实施：

1. 渲染器按首次出现顺序确定编号，同一来源复用编号，多个来源使用稳定顺序；不得由模型编造脚注。
2. 正文、表格和静态图来源均进入同一附录，摘要事实值、期间、范围、方法和源文件业务名称，不嵌入完整明细。
3. stale/unbound/缺文件等状态按文档规则表达，不能隐藏失效并保留“有效来源”样式。
4. 在线定位链接指向 report/revision/subject，不带会话 token；缺登录或权限时走现有授权边界，文件内摘要仍可阅读。
5. 与 B6 同一快照联合渲染；旧报告和来源关闭配置仍能导出。

验证：两种格式实际检查文本和视觉；多次引用、跨页表格、长中文名、多个 CSV、待复核内容、无来源旧报告、授权过期；编号与在线对象对应。

G8：PDF、Word、Markdown、来源索引版本一致，脚注和状态无冲突；文件头正确不能代替内容验收。

交付：渲染接入、附录模板、导出配置、双格式验收样本。

### B9：完整验收与发布

实施：

1. 按 F01～F12 清单逐项验收，不以少数 happy path 或面板点击率代替功能完成。
2. 验证进程重启、workspace 重新注册、部署恢复、共享源文件保留/过期和导出任务失败恢复。
3. 按 B0 规模压测预览、依赖展开、下钻与导出；比较输入/保存主路径和内存峰值。
4. 使用来源登记、面板、下载、下钻、导出展示独立开关，先内部、后逐步扩大；关闭展示不删除历史证据。
5. 准备运维说明、错误定位、回滚和已知旧报告限制；记录当前不可用来源的真实原因。

G9：全部适用功能通过，阻断缺陷清零；没有未解释的错误有效绑定、越权读取或跨版本错配；旧报告正常使用；性能、恢复和双格式导出通过。真实审核人员能完成事实、图表、复杂分析和 CSV 核对任务。

## 9. 测试数据与独立答案设计

### 9.1 基础三份报告

输入 CSV 使用四条可手算记录：8 月 A 收入 1000/人次 10、8 月 B 收入 2000/人次 20、9 月 A 收入 1200/人次 10、9 月 B 收入 2400/人次 20。单位为测试约定的元，不能与效果图的万元混用。

| 场景 | 固定答案 | 验证目标 |
| --- | --- | --- |
| R1：9 月全部院区 | 收入 3600、人次 30、次均 120、环比 20% | 值、期间、公式、CSV 身份正确 |
| R2：9 月仅 A 院区 | 收入 1200、人次 10、次均 120、环比 20% | 本期和基期都受同一范围限制 |
| R3：从 R1 人工改收入为 3800 | 当前正文 3800；生成 fact 3600；对应绑定 stale | 保存/恢复/导出不把旧来源当作新值证明 |

### 9.2 补充必测集合

- 图表数据集：类别排序、Top N/其他项、缺值、单位转换、正负数、多系列；冻结实际作图表的独立答案。
- 多步 facts 数据集：贡献分解、分子分母依赖、重复 join、零分母、缺失期间；手算关键中间值。
- 统计分析集合：覆盖 B0 清单中实际方法，固定样本数、预处理和参数；采用独立算法或已知数学例核验，记录容差。
- CSV 边界集合：引号、换行、空行、长字段、宽表、大小边界、同名不同身份、授权字段差异和派生下载。
- 生命周期集合：原版、手改版、重新分析版、历史恢复版、故障提交与共享文件清理。
- 旧报告集合：无索引、有 citation 无精确 fact、CSV 缺失、附件 CSV 缺时间等，均有明确兼容表现。

不要求业务人员手写完整测试报告。工程人员准备合成数据、产物及对账脚本，业务人员确认指标口径和真实审核任务。合成测试证明实现行为，真实样本证明对业务数据的适配，两者不能互相替代。

### 10.3 最终端到端验收脚本

1. 生成报告，完成 CSV、facts、图片、作图数据、来源索引和 PDF/Word 的登记校验。
2. 打开 Editor，从正文与一个结构化单元格定位 facts，再打开各自 CSV。
3. 打开静态图来源，核对实际作图表、方法和全部输入。
4. 展开复杂分析，核对中间结果和多个输入事实，辨认估计与解释。
5. 分页预览和按不同权限下载原始/派生文件，验证字段与身份。
6. 执行允许下钻和不可用维度场景，核对算法及拒绝行为。
7. 修改数字、表格和图注，保存、冲突、撤销和历史恢复，确认状态准确。
8. 导出 N+1，检查双格式编号、附录和在线定位；旧版仍指向旧输入。
9. 重新分析生成新数据，确认旧版结果不变；模拟源文件损坏/缺失，报告仍可编辑。
10. 重启与恢复，验证共享文件清理及授权；关闭功能开关，普通报告编辑导出继续工作。
