Trusted Word input builder design (0ce3aa10)
Only a new unregistered internal builder and tests. Constructor receives existing grants/native services. build(scope, server_session_reference, instruction, expected_sha256, operations, selection) returns NativeWordTaskInput, never schedules or creates a production task. Trusted caller supplies TaskExecutionScope (executor/workspace policy), not browser/model. Builder checks owner/thread against recovered four-part native scope. Every authority/hash/allowed-operation field is derived from the registered-session/context/source/selection chain.
Before first await: validate instruction without trimming its hash; canonical serialize/limit/copy base operations and selection; reject non-body paragraph selection. Session reference is internal hash, never returned in errors/logs. Recover registered session then native context, require DOCX and native enabled. Check expected SHA only for stale request, preview source with [], selected_word_objects on private base/selection, preview(base), map strict selected fields into DTO. Snapshot reuses NativeAIService._snapshot; other digests use canonical_digest. End: lookup registered session/context again and compare full session+context identity, rejecting observed expiry/missing/change. This is not linearizable cross-service revocation and does not authorize later MCP/commit/acceptance.
No real Codex/worker/SDK/HTTP/route/token and no shared lifecycle/schema edits. Existing MCP synthetic three-tuple remains offline. Real synthetic DOCX/preview/selected tests plus controlled registered-session repository; atomic create tested only in disposable PG with fixed test scope. Never queue an actual production task.
Alternatives: direct production MCP rejected (no trustworthy identity/worker boundary); worker deployment isolated identity needed later but cannot be established by same UID scratch/env shaping. Builder is useful prerequisite without claiming runtime integration.

Reviewed concrete limits: before first await instruction must be nonblank and at most 2000 characters (hash retains exact whitespace); operations list at most 500 and canonical bytes at most 12 MiB; selection list 1..100 with each item exactly {blockId}. Actual source paragraph type is verified after source preview, not inferred from selection shape. Initial registered session identity is immediately canonicalized into a private snapshot of report/revision/workflow/context digest/expiry/capabilities, including mutable capabilities, not retained by object reference. Final lookup/context is compared to those private identity bytes. Request copies alone are used across awaits. Normalize the final DTO again to strip/forbid unknown fields. The internal DTO includes the session reference but must never enter generic serialization/errors/logs.
Required actual DOCX tests include source bytes changing between previews; registered session deletion/expiry/in-place capabilities mutation; context replacement; caller operations/selection mutation during awaits; nonparagraph selection; forged expected object hash/allowed operations. Scope checks do not make request expectedSha an authorization source. Source bytes are independently verified by existing preview/read machinery. Observed validity is not a linearizable instantaneous revocation guarantee.

Review correction: after final context await, relookup registered session and compare the private identity again; after every await is complete check expiry against fresh synchronous UTC time. This blocks observed registry removal during context recovery and natural expiry even if an earlier lookup captured time before awaiting repository IO. It still cannot linearize context/session authorization across different services or prevent revocation immediately after return. Selected block IDs are 1..256 characters.
