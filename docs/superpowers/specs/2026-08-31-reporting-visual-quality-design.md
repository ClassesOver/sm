# Reporting 可视化质量与章节展示优化设计

## 目标

提升 Reporting CLI 生成图表在 PDF、Word 和 HTML 中的可读性与版面质量，同时保持图表选择自由度以及现有事实、citation、文件身份和发布验收契约。

本次只解决以下问题：

- 分类轴出现完整科室或数据集路径，导致标签过长且字号不可读。
- 图表像素尺寸或正文有效 DPI 偏低，但现有检查只覆盖较低的基础分辨率。
- TopN、长标签和双指标小样本图缺少明确的布局指导。
- 章节装配对不同纵横比图表采用相同展示规则，容易出现图表过小或分页留白失衡。

## 非目标与不变量

- 不固定图表类型，不引入模板白名单。
- 不改变 `visualInspectionMode` 的选择逻辑。
- 低分辨率和可读性风险只产生质量告警，不拒绝图表登记、章节装配或发布。
- 不放宽或重写 `chartIds`、metric、citation、事实文件、文件哈希、Manifest 和发布验收契约。
- 不修改图表中的业务数值、指标定义、期间或可比性语义。

## 图表生成协议

扩展现有 `report-visualization` Skill 和可视化 Worker 指令，提供以下约束：

1. 分类轴标签必须使用能唯一识别对象的最短业务名称。完整组织层级、日期、数据集路径和血缘信息不得直接作为坐标轴标签，应放入正文、表格、脚注或图表说明。
2. TopN 和长标签比较优先使用横向条形图；根据项目数量动态调整画布高度，并对仍然过长的标签进行语义缩写或换行。
3. 只有两个或少量指标的比较，应根据管理问题选择紧凑对比图、哑铃图或表格，避免用大面积普通柱状图承载极少信息。
4. 保存图表时目标像素尺寸不低于 `1200 x 675`；布局必须保留标题、坐标轴、图例和数据标签的安全边界。

这些规则是生成指导和质量标准，不限制模型根据数据选择其他更合适的图形表达。

## 非阻断质量检查

图表登记继续执行现有格式、文件大小、空白图片和路径检查。在此基础上增加结构化质量告警：

- 图片宽度小于 1200 像素或高度小于 675 像素时记录 `chart_low_resolution`。
- 按 A4 正文可用宽度和最终展示宽度估算的有效分辨率低于 150 DPI 时，记录 `chart_low_effective_dpi`。
- 告警包含 `chartId`、实际像素尺寸、阈值和估算 DPI，不包含图片正文或敏感业务内容。

上述告警进入既有 warnings 链路，但不抛出 `ReportingError`，不阻断登记、冻结、章节装配或发布。

## 章节展示与分页

章节装配继续只按冻结的 `chartIds` 引用图表。服务端渲染根据图表纵横比附加确定性的展示分类：

- 标准横向图：使用正文可用宽度，保持原始纵横比。
- 超宽图：使用正文全宽，并避免与后续标题或说明分离。
- 偏高图：限制最大显示高度，保持等比缩放，避免单图挤占不合理页面空间。

图片、图注和紧随其后的说明形成不可拆分的分页单元；章节标题不得单独落在页尾。展示分类只影响 HTML/CSS 和 Word 图片尺寸，不改变 Markdown 图表路径、图表顺序或任何产物身份。

## 测试与验收

采用定点测试验证：

1. `1199 x 675`、`1200 x 674` 等边界图片产生低分辨率告警，但仍成功登记。
2. 有效 DPI 低于 150 时产生独立结构化告警且不阻断登记。
3. 可视化 Skill 和 Worker 指令包含短标签、TopN 动态高度及小样本紧凑表达要求。
4. 不同纵横比图表获得稳定的展示分类和尺寸规则。
5. 章节装配后的 `chartIds`、图表路径、文件哈希和 Manifest 验收行为保持不变。
6. PDF、Word 渲染现有定点测试继续通过，不出现图片丢失、标题孤行或图注分离。

## 风险控制

- 有效 DPI 是基于确定性页面参数的估算值，只用于发现风险，不作为发布门禁。
- 生成指导可能改善新报告但不会重绘历史产物；历史回放保持原有图表文件。
- 展示规则集中在现有渲染层，不向章节模型暴露新的事实修改能力。
