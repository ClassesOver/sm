# Report Editor 来源追溯 UI 实施计划（B5 细化）

日期：2026-10-02

状态：设计与实施计划；未实现。

上位文档：`2026-09-29-report-editor-data-lineage-batched-implementation.md`（B5、B6 相关部分）、`2026-10-02-report-lineage-b0-freeze.md`（V1 契约与待决项）。

本文只覆盖 Report Editor 前端的来源入口、来源抽屉、表格预览和状态展示，以及它们需要的最小后端字段。后端 CSV、facts、图表和计算记录服务分别由 B1～B4 交付。

## 1. 前端现状（已核对代码）

| 事实 | 位置 | 对 UI 设计的影响 |
| --- | --- | --- |
| 正文协议标记只有 `section`、`citation`、`analysis` 三种，以内联装饰呈现；`citation` 显示为“引用”小标签，`contenteditable=false` | `src/protocol.ts`、`src/protocol-plugin.ts` | 引用标签已经是天然入口，但目前不可点击，也不携带可供无障碍读取的名称。 |
| 生成器把 `[[citation:…]][[analysis:…]]` 追加在每个正文块末尾；图表图片后紧跟其 citation 标记 | `reporting/delivery/draft_v1.py` `_marker_lines`、`_chart_figure_markdown` | 标记定位到“块”，无法定位到块内具体数字。 |
| `SectionArtifact` 的 claimIds 不进入最终 Markdown | 同上 | Editor 无法从正文直接得知某句话对应哪个 claim，需要后端提供“块 → subject”映射。 |
| `[[table:…]]` 只出现在保留标记和 manifest 正则中，当前没有任何代码生成它；正文表格是模型写的普通 Markdown 表格 | `draft_v1._RESERVED_BODY_MARKERS`、`artifacts_v1._TABLE_BLOCK` | 单元格级入口要等 B2 新增服务端结构化表格后才能实现。 |
| 协议插件的 `filterTransaction` 会拒绝任何改变标记序列的编辑 | `src/protocol-plugin.ts` | 标记在编辑期间不会被删除、复制或重排，可以作为稳定锚点；含标记的块也无法被整体删除，这是现有行为，不在本计划中改变。 |
| 交互图表以覆盖层方式挂在 `body` 上，按图片位置定位，不进入 ProseMirror 文档 | `src/interactive-charts.ts` | 图表来源按钮沿用同样的覆盖层方式，不往正文插入节点；Plotly 覆盖层也需要显示该按钮。 |
| 弹窗原语 `createModal` 自带焦点陷阱、Esc 关闭和焦点归还；历史面板基于它实现 | `src/modal.ts`、`src/history.ts` | 移动端的全屏来源面板可复用；桌面端为了让用户边看来源边编辑，需要非模态抽屉，不能直接复用。 |
| 构建预算：入口 ≤180 KiB，其他 chunk ≤250 KiB；搜索、历史、交互图表均按需 `import()` | `scripts/check-build-budget.mjs`、`src/main.ts` | 来源模块必须懒加载，不进入入口 chunk。 |
| API 客户端统一走 `ReportEditorClient.request`，携带 CSRF，错误映射为 `ReportEditorApiError(status, code, requestId)` | `src/api.ts` | 来源接口加到同一客户端，复用错误码和 requestId 展示。 |

## 2. 设计原则

1. 不改变现有编辑主流程：来源模块加载失败、接口报错或功能关闭时，正文编辑、保存、历史和导出完全不受影响。
2. 入口只出现在服务端登记过来源的对象上，前端不靠“附近的数字”或文本匹配猜测来源。
3. 状态如实展示：文件完整只说明文件可读、未被篡改，不等于数值已核对；没有对应能力时显示原因，不显示“已验证”或“已脱敏”。
4. 默认界面只展示业务名称、期间、范围、方法和限制。JSON Pointer、完整 hash、DatasetLineage 只出现在“技术详情”折叠区。
5. 查看来源不触发查询或计算，也不生成新的 revision。

## 3. 入口设计

| 入口 | 触发对象 | 打开后的默认页 | 依赖批次 | 说明 |
| --- | --- | --- | --- | --- |
| E1 引用标签 | `[[citation:…]]` 装饰 | 数据快照 | B1 | 只能定位到数据集，界面写“引用的数据集”，不写成“这个数字的来源”。 |
| E2 段落来源 | 含 `[[analysis:…]]` 或有 subject 映射的正文块 | 分析依据 | B2 | 在块的右侧边栏显示小图标按钮，鼠标悬停或光标进入该块时出现；触屏设备常显。 |
| E3 图表来源 | 已登记 ChartTrace 的图片（含 Plotly 覆盖层） | 作图数据 | B3 | 图片下方覆盖层按钮“查看图表来源”；不做图内数据点点击。 |
| E4 计算过程 | 抽屉内事实详情中的“计算过程”链接 | 计算过程 | B4 | 不在正文单独设入口，避免入口过多。 |
| E5 单元格来源 | B2 新增的服务端结构化表格单元格 | 分析依据 | B2（结构化表格） | 当前没有结构化表格，E5 在 B2 交付前保持关闭；普通 Markdown 表格不提供单元格入口。 |
| E6 来源概览 | 工具栏“来源”按钮（放在“编辑与视图”组） | 概览列表 | B1 | 列出本报告的所有数据集、分析和图表，可跳转到正文位置。 |

块级定位规则（E2）：

- 后端在 `GET /sources` 中返回 `blocks: [{blockAnchor, subjectIds}]`。`blockAnchor` 由该块末尾的标记序列和块序号组成，前端按同样规则在文档中定位。
- 一块内有多个 subject（多个 claim）时，抽屉顶部列出这些 claim 的生成时值和指标名，用户点选后看具体事实；不在正文中尝试把每个数字高亮成独立入口。
- 是否引入新的内联 `[[subject:…]]` 标记以做到“数字级”入口，见待决项 U-Q1。本计划默认不引入。

## 4. 来源抽屉

### 4.1 布局

| 宽度 | 形态 | 说明 |
| --- | --- | --- |
| ≥1181px | 右侧非模态抽屉，宽 420px，可拖宽到 720px；正文区域相应收窄 | 用户可以一边看来源一边编辑；焦点不被锁定，Esc 关闭并把焦点还给入口。 |
| 769～1180px | 右侧覆盖式抽屉，宽 min(420px, 60vw)，不推挤正文 | 是否改为推挤正文见 U-Q2。 |
| ≤768px | 全屏面板，复用 `createModal`（模态、焦点陷阱） | 顶部带返回按钮，表格可横向滚动。 |
| 宽表 | 抽屉内“展开”按钮切换为 `variant: 'wide'` 的大面板 | 仍是本报告内的视图，不建设独立数据应用。 |

抽屉结构：

```text
┌ 标题：对象名称（如“9 月门诊收入”）      [展开] [关闭]
│ 状态行：内容 有效/待复核 · 文件 可用/缺失/过期/校验失败
├ 页签：分析依据 | 计算过程 | 数据快照 | 作图数据（按对象类型显示）
│ 页签内容
└ 技术详情（默认折叠）：resourceId、指针、文件身份摘要、requestId
```

### 4.2 各页签内容

| 页签 | 展示 | 数据接口 |
| --- | --- | --- |
| 分析依据 | 生成时值、当前正文值（若可取得）、指标、期间、范围、聚合/公式；比较事实同时列本期与基期；比率列分子分母；对账列容差与失败组数；输入事实一层，可逐个展开 | `GET /sources/{subjectId}`、`GET /facts/{factRefId}` |
| 计算过程 | 方法与版本、参数、预处理步骤、中间表（可预览）、输出事实、限制、验证状态、复算能力 | `GET /facts/{factRefId}` 中的计算记录 |
| 数据快照 | 文件名与业务名称、期间角色、来源类型（查询/上传）、行数、物化时间（未知则写“未知”）；分页表格；下载按钮（按能力显示） | `GET /datasets/{id}/preview`、`/download` |
| 作图数据 | 作图表（分页表格）、类别列与系列映射（名称、单位、主/次轴、观测/预测/区间）、转换说明、来源 CSV/事实链接、视觉检查状态 | `GET /charts/{chartId}/source` + 预览接口 |

### 4.3 有界表格视图（`data-grid`）

- 每页默认 50 行，可选 100；最多 50 列，超出列通过“选择列”控件选择；单元格超过 4 KiB 显示截断提示。
- 翻页只用服务端签名游标；不在前端拼接 offset。
- 表头固定、首列固定；行号显示“快照第 n 行”，与服务端稳定顺序一致。
- 响应因字节上限返回不足一页时，显示“本页因大小限制只显示 k 行”，不伪装成完整页。
- 不做前端求和、排序、筛选，避免用户把前端计算当成报告口径。
- 文件角色以标签区分：输入 CSV、作图数据、中间表。

## 5. 状态与文案

后端按 V1 契约返回独立的状态维度，前端组合展示，最多同时显示两个状态标签，其余放在技术详情中。

| 情况 | 状态行 | 正文/按钮行为 |
| --- | --- | --- |
| 加载中 | 骨架屏 | 切换对象时中止旧请求（`AbortController`），并按请求序号丢弃迟到响应 |
| 无来源（旧报告或未登记对象） | “该内容没有登记来源” | 不显示入口；从概览进入时显示该说明 |
| 内容 stale | “正文已修改，以下为生成时依据，需复核” | 依然可看旧证据 |
| 内容 unbound | “未能确认该内容对应的来源” | 不展示事实值 |
| 文件 missing / expired | “数据快照不可用（已缺失/已过期）” | 隐藏预览和下载，元数据仍可读 |
| 文件 integrity_failed | “数据快照校验失败，已停止读取” | 不显示任何文件内容；报告编辑不受影响 |
| 无权限 | “当前链接无权查看数据明细” | 按钮置灰并说明原因；不显示字段名 |
| 资源超限或超时 | “请求过大或超时，请缩小范围后重试” | 提供重试按钮，不静默截断 |
| 计算 verified / not_checked / failed | “已独立核对” / “未独立核对” / “核对未通过” | not_checked 不使用成功色 |
| 证据性质 interpretation | “业务解释，非计算结果” | 列出支持事实 |

所有错误都显示 `requestId`，沿用 `src/error-labels.ts` 的错误文案映射，新增 9 个 V1 错误码的中文文案。

## 6. 与编辑流程的交互

| 场景 | B5 行为 | B6 完成后的行为 |
| --- | --- | --- |
| 编辑含来源的块 | 入口旁显示“已修改”提示，抽屉状态行写“正文已修改，来源状态以保存后的校验为准” | 本地立即标“校验中”，调用 `POST /sources/validate`，响应必须匹配当前草稿版本，否则丢弃 |
| 保存 | 无额外行为 | 用保存后的 sha 重新拉取 subject 状态 |
| 撤销到原文 | 提示保留到下一次校验 | 校验通过后恢复 valid |
| 打开历史版本 | 历史面板中的旧版本不提供来源入口 | 历史预览使用该 revision 自己的来源索引 |
| 导出 N+1 后跳转新版本 | 新页面重新加载来源 | 新 revision 的来源由服务端继承，未变化对象保持 valid |
| AI 改写被接受 | 等同人工编辑 | 同左 |

B5 阶段只显示“正文已修改”，不给出 valid/stale 的结论；正式的有效状态展示在 B6 通过后开启（与上位计划 G5/G6 一致）。

## 7. 前端模块划分

| 模块 | 职责 | 加载方式 |
| --- | --- | --- |
| `src/sources-api.ts` | 在 `ReportEditorClient` 上增加来源接口与 DTO 类型；DTO 字段与 `trace_v1.py` 对齐 | 随 `api.ts` |
| `src/source-anchors.ts` | 从文档和 `/sources` 结果计算块锚点、引用标签和图表映射；纯函数，便于单测 | 懒加载 |
| `src/source-entry-plugin.ts` | ProseMirror 装饰：引用标签可点击、块侧入口按钮；不修改文档内容 | 懒加载 |
| `src/source-chart-entries.ts` | 图片与 Plotly 覆盖层下方的“查看图表来源”按钮，复用 `interactive-charts.ts` 的定位逻辑 | 懒加载 |
| `src/source-panel.ts` | 抽屉、页签、状态行、技术详情、请求取消 | 懒加载，首次点击入口时载入 |
| `src/data-grid.ts` | 有界表格、列选择、签名游标翻页 | 随 `source-panel` |
| `style.css` | 抽屉、入口、状态标签、表格样式，复用现有按钮与面板头部类 | 现有文件 |

开关：`GET /api/document` 增加 `sources: { enabled, capabilities: [...] }`。字段缺失或 `enabled=false` 时不加载任何来源模块，界面与现在完全一致。`capabilities` 决定是否显示预览、下载、下钻按钮（对应 B0 待决项 Q1）。

## 9. 验收标准

1. 来源功能关闭或模块加载失败时，正文编辑、保存、历史、导出与当前版本行为一致。
2. 入口只出现在服务端登记的对象上；R1 的收入、人次、次均、环比从入口到事实再到 CSV，数值与 `expected_answers.json` 一致；R2 的本期与基期都显示 A 院区范围。
3. 快速切换 10 个对象后，抽屉只显示最后一个对象的内容。
4. 100 行 × 50 列预览渲染期间，正文输入无明显卡顿（以浏览器性能面板中长任务 <50ms 为准）。
5. 状态组合不会把“文件可用”显示为“数值已核对”；无权限时不泄露字段名。
6. 新增来源 chunk 不超过 250 KiB，入口 chunk 增量不超过 5 KiB。
7. 键盘可完成打开、切换页签、翻页、关闭；移动端（390px 宽）无横向页面滚动，表格在面板内横向滚动。
8. fixture-server 只用于界面验证；授权、真实文件和状态必须在真实后端上验收（U7）。
