# 智能报告：指标、统计口径、知识依据与报告计算依据

**状态：** 隔离工作区实施中；新契约/存储基础和原文解析已定点验证，工作流切换与业务验收尚未完成。
**日期：** 2026-11-09。
**最新决策：** 用户明确要求“冻结 Profile 有点抽象，参考成熟的专家设计”“不做兼容”“更新计划”。本文件取代本轮早先以旧 Profile 为权威、伴随扩展、兼容恢复的草案；与旧管理总计划冲突时以本文件为准。

## 1. 目标与首期边界

用一类真实报告、三个关联指标，把“定义可理解、数字可核对、解释有出处、修订可追溯”做成闭环。建议试点“月度预算执行专题”：预算额、实际执行额、执行率。该试点是工程建议，实际字段和业务定义必须由原始材料与业务签认确定；未签认前只称合成验收，不冒充真实业务结论。

首期不做通用BI、通用公式语言、图数据库、多角色审批、查询限额管理或负责人表单。不部署完整MetricFlow/Cube/OpenMetadata平台。复用现有Agno、SQLGlot、数据访问与产物追溯代码；复用算法不等于保留旧协议。

## 2. 产品模型：四个业务对象

| 对象 | 用户要回答的问题 | 核心内容 |
| --- | --- | --- |
| 指标定义 | 是什么，怎么算？ | 稳定指标编码、名称、公式类型、字段或依赖指标、单位、业务粒度、时间字段、允许维度、聚合性质 |
| 统计口径方案 | 哪个场景采用哪套规则？ | 名称、版本、报告场景、适用组织/期间、精确指标版本、纳入/排除条件、已批准关联、累计处理规则、制度依据 |
| 业务知识 | 规则或解释依据在哪里？ | 原始文件修订、原文位置、生效期、适用组织、用途、审核事件；发布为明确的证据集合 |
| 本报告计算依据 | 本次实际怎么算出来？ | 所用口径和指标版本、组织/期间、数据截止与提取时间、SQL和结果身份、引用、假设、告警、报告修订 |

用户界面不出现Profile、hash、冻结对象或向量索引代次。技术身份只在授权技术详情中展示。报告入口显示“本次采用：月度预算执行口径，第2版”，报告数字旁以“计算说明与来源”为统一入口，提供“查看计算明细 / 查看制度依据 / 对比版本”。

指标与口径是独立业务资产，不再把它们混装到包含页眉/品牌/文档版式的Profile。数据源只负责连接和表目录；统计口径绑定其使用的数据源/字段。口径发布不要求无关的数据连接重新发布。报告版式和品牌使用独立交付设置，避免规则改变引起排版版本漂移。

## 3. 不兼容的明确边界

- 新业务模型使用新契约；删除`ReportingProfileDocument`、`EffectiveReportingProfile`、`reportingProfileVersionId`、旧Profile API和文件Profile加载器的运行依赖。
- 不提供旧字段别名、自动转换、兼容代理、旧配置回退、旧新双写或双轨运行。
- 旧运行不能继续或恢复执行；返回明确的`report_contract_retired`，引导用户按新口径创建新报告。此限制只适用于旧执行契约，不影响新模型内正常暂停/恢复。
- 不自动迁移旧JSON为正式新规则。根据原始制度、实际字段与签认案例重新登记和发布。历史数据不因“不兼容”自动删除；上线执行删除/清理属于另行明确操作。
- 已生成历史PDF/Word仍作为产物按既有授权及文件身份规则访问；不解析旧Profile、不重新计算、不提供旧规则编辑/重导出适配。历史编辑/恢复入口返回停用说明。
- 后端、管理UI、报告入口、Editor依据展示按同一版本切换，不做旧客户端兼容。切换前停止接受旧契约新运行；旧正在运行任务完成后切换，不能完成者显式结束并创建新任务，不假装成功迁移。
- 数据库采用增量DDL创建新表，旧Profile表保留归档但无线上读写；不重写历史记录hash。现有迁移历史文件保留用于数据库升级，不代表保留旧业务运行逻辑。
- “Profile”同名的LLM模型配置、数据画像、图表画像不属于旧业务Profile，不得全局字符串替换误伤。

## 4. 版本与生效

指标、统计口径、文档修订和证据集合发布后不可变。编辑产生草稿，新发布产生新版本。发布口径后，管理员明确“设为新报告默认”；默认绑定按组织与报告场景管理，使用CAS，不偷偷取最新版本。

报告创建时由服务端校验身份、组织、表暴露范围、指标依赖、口径适用期，并登记“本报告计算依据”。同一runId重试和新模型运行恢复读取这份记录。UI/session_state/模型工具参数不能替换服务器登记的依据。

口径业务生效区间左闭右开，另存系统登记时间。跨越口径边界时只按已明确配置的分段方案计算；首期未登记分段方案时返回不可比较原因并继续其他分析，不猜测整期口径。更换规则重算产生新报告修订并展示差异。

数据源新发布可以改变新报告允许范围，但不授予口径中引用的未暴露表；默认口径引用不可用对象时显示具体缺失和不计算原因。旧新模型运行恢复仍受各自登记的授权范围与当前访问撤销规则约束。

## 5. 计算与知识边界

首期执行sum、count、count_distinct、ratio和已明确的累计快照策略；比率按聚合后分子分母重算，内部Decimal不提前舍入。预算与实际分别聚合到相同粒度再关联，不按明细JOIN放大金额。关联仅允许已登记的多对一维度路径，执行前检查唯一性；多对多和无分摊规则的细粒度预算请求不生成伪值。

所有查询经过既有只读SQL解析、组织约束及表允许范围验证，动态标识来自服务端登记，过滤值参数化。知识文本/示例SQL/模型建议不能改变执行权限或正式公式。

知识角色为制度依据、定义说明和背景材料。经审核并绑定到已发布口径的资料才能作为该口径正式依据。原始文件、定位文本、解析版本、分块与集合身份一并保存。检索先按可信组织及本次证据集合过滤，再排序；不能把跨组织正文交给模型后过滤。

知识索引是可重建派生数据。文档原件与已审核修订存储为权威；索引失败保留任务与故障状态，不生成“已发布可用”的假成功。新文档、新索引不会改变已经生成的报告依据。引用原文中包含工具指令只作为数据处理。

## 6. 追溯与软告警

链路：问题→指标候选→消歧→口径适用性→检索依据→计算计划→取数→核对→解释与引用→编辑修订。

每个数字关联指标版本、计算参数、查询与数据集身份；每个有依据的解释关联原文定位。区分事实、推断、建议。缺少证据时保留“推断/未证实”标记；语义不确定只形成可解释软告警，未解决指标无值并给原因，其他报告内容继续。

配置不变不代表数据不变。首期可重现承诺为：在保留且身份可核验的CSV/计算记录和证据快照上复核数值与引用；不承诺数据源后续重跑同值、跨查询数仓全局一致快照或自由文本字节一致。多次查询记录各自提取窗口和数据水位，无法保证一致性时披露。

证据访问被撤销时当前授权优先，不读取被撤销内容，旧报告显示依据不可访问。已有PDF/Word是否可下载仍按其已签发授权与身份处理，不因语义/溯源失败新增下载阻断。

## 7. 验收与非目标

原始材料：制度原件、单据状态、DDL/视图/ETL、实际SQL/Excel公式、签认报表、差异处理与真实运行日志。只采集已授权材料；凭据和敏感明细不写入计划或仓库。

38个固定案例（原30项加闭环反例8项）；定义、数值、权限、版本和恢复结果须逐例符合预期。金额两位小数误差≤0.01，执行率展示误差≤0.01个百分点；期望无值的案例不能补0。独立oracle不调用生产公式/编译器。

有明确标准依据的问题，Top-5召回目标≥95%并报告分子/分母；跨组织/不适用文档泄漏0；引用定位身份有效率100%。解释是否被证据支持由独立业务抽查确认，模型评分不代签。小样本不代表所有业务正确。

新UI沿用Report Editor的浅色视觉、Noto字体、#0B4F8A主色；1440/1280/768/390px无整页溢出，axe严重/关键0。登录≤300KiB、列表累计≤500KiB gzip，新增页面懒加载。

应用loguru；图表仅Matplotlib静态PNG/JPEG。使用隔离管理PG与唯一隔离StarRocks库；业务库不做重置、授权或故障实验。只运行受影响集合，不重复完整项目测试。验收失败不阻止已生成且身份可读取的PDF/Word签发，必须明确失败原因，不可标记通过。

缺业务签认、真实embedding或模型环境时独立登记为未执行。合成数据、mock、离线回放、真实StarRocks及真实AgentOS报告必须分开交付证据。


## 8. 报告闭环补充审查（2026-11-09）

以下补充属于原有三个指标试点的完成条件，不扩大为通用分析平台。相关基础能力已部分存在；要求证明新模型贯穿使用，不能从计划缺项推断代码一概缺失。

### 8.1 从用户问题到回答覆盖

报告发起时登记用户目标、组织、期间、比较基准、单位、输出形式及待回答问题。区分输入的明确值、系统默认和未解决项；只有改变结论的歧义才请求澄清，未回答时将相关分析标为未解决，其他内容继续。每个问题通过稳定ID关联分析、事实和报告位置，完成状态为answered/partial/unavailable及具体原因；报告完成不等于所有问题已回答。

### 8.2 数据是否足以回答

取数回执增加数据就绪情况：要求期间与实际覆盖、更新时间/可得水位、必需字段、重复键、单位、币种、实际与预算的组织/粒度对齐。规则与阈值由统计口径明确声明，无规则时标unknown，不臆造正常。缺月、未更新、部分提取不得解释为经营下降，未匹配金额不得在INNER JOIN中静默丢弃。受影响分析无值或披露限定范围，不影响其余报告和已有产物下载。

同比/环比明确基期、组织边界及口径可比性；没有可比条件不计算误导性增长率。首期只支持试点所需比较，新增算法不扩为通用时间智能。

### 8.3 正式规则和当期背景分开更新

制度/定义依据仍由统计口径引用精确证据集合；项目延期、预算批复等当期背景可发布为独立背景集合，不能迫使管理员修改公式版本。创建报告时分别登记规则依据集合和明确选定的背景集合版本；无显式选择时使用同组织同场景已发布的背景默认绑定，没有绑定则不附加背景。不在运行中读取最新集合。

背景检索仍按授权组织、报告期间、项目/对象匹配和发布状态限制。文档发生时间与生效时间分别记录；历史报告不得把后来才知道的事件当成当时已知事实。背景材料可支持解释，不修改正式公式和计算权限。

### 8.4 从数值到结论、图表和导出

统一事实身份串起指标值、表格单元、图表点和正文数字；数值/单位/范围/舍入由同一事实投影，不能各自重新计算。正式结论记录类型fact/inference/recommendation及支持证据。来源链接存在只证明引用可定位，不证明因果成立；“支出下降”不能仅凭相关性写成“采购延期导致”。缺因果证据时标待核实解释或建议。

PDF/Word附带可读的计算说明和来源摘要，线上链接使用现有受控访问；下载授权不自动包含原始明细或制度全文权限。导出引用故障记录问题但继续签发实际产物。

### 8.5 编辑、重算和修订一致性

区分文字润色、解释修改、指标/期间/数据重算。按现有追溯关系将受影响对象标stale或待核对：重算输入→数字→图表/表格→结论→导出修订。未变部分可以复用，但只有身份和依赖一致才能沿用核对结果。手工覆盖数字保留为明确的人工修订，不反向修改正式指标或冒充重新执行SQL。

同一重算请求使用稳定request_id和输入摘要去重；相同ID不同输入返回409；响应丢失读取任务与实际revision状态。实际产物登记以report_revision为边界，不能把旧图和新结论标为同一已验证版本。

### 8.6 错误反馈到受控改正

在“计算说明与来源”中提供问题反馈：数值、口径、数据、引用、解释五类；记录报告修订、相关metric/subject/document身份、描述和可选佐证，不增加负责人字段或角色系统。管理员在既有身份下核对，结果为accepted/rejected/needs_evidence并有理由。

采纳后生成候选规则/知识修订及对应反例测试，经明确发布后可选择重算新报告修订；不自动在线学习改正式规则，不覆写原报告。问题关闭记录处理版本、测试结果和新修订；未重算也要明确说明。纠错行为本身成为以后验收可重放的案例。

### 8.7 发布影响、停用和替代

发布/设默认前按显式版本引用计算影响：哪些口径、默认场景、报告依据使用旧资产；不做全企业血缘平台。发布新版本不自动改变旧报告。错误版本支持独立的退役记录和替代版本建议，不能改写已发布内容；退役仅阻止新选用，已有新模型运行可按原依据完成并披露问题；安全撤销按当前授权禁止使用对应资源。

默认绑定指向退役版本时不得偷偷选最新，应要求明确替代并以CAS保存；可提供报告缺配置说明，不制造成功计算。

### 8.8 证据保留与故障恢复的实际承诺

报告依据记录`reproducible_until`及所依赖原件、定位文本、数据集、计算记录和代码构建身份。期限取部署保留策略与各资源可用期限的最短值；缺期限信息标unknown，不承诺永久复现。业务计划不擅自指定实际保留天数。

报告引用形成资源保留引用；在保留期内，现有清理任务不得将其当孤儿删除。到期或依法/按当前授权撤销后，依赖核对显示“原始依据不可用”，保留允许保留的最小审计事实，不伪造重现成功。备份恢复必须联合验证PG、文档/CSV和派生索引；索引可重建，原件缺失不能靠重建索引掩盖。
