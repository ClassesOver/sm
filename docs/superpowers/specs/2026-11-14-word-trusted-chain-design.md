# Word trusted task/MCP/acceptance chain (proposed)

Baseline code 1e4a0a34 includes #236 persistence and #239 builder. No runtime isolation is verified; real Codex startup remains forbidden.

## Architecture and ownership
A WordTaskCoordinator is a narrow internal service using existing TaskSession and repository open/resume/request_finish/finalize/cancel operations, not a new agent loop/runner. Existing Agno/Codex adapter owns provider execution; coordinator receives a transport with one run call and no shell/files/database. No fallback to regular Agno when Word task dispatch is selected but unavailable. Runtime_gate owns isolation verification, not a second bridge or credential issuer. unified_office owns TS task control; frontend sees editId/clientRequestId and existing running/terminal/status/events/accept, not owner/epoch/native scope or executor choice.

Only Word DTOs are persisted. Start derives trusted task scope/executor/workspace via server policy and builder, atomically creates task/input, then current TaskSession claims/open run. A Word-only HMAC credential uses a separate required secret and audience, short TTL at most60s, and binds task scope, NativeScope4, input digest, owner/epoch/run/attempt/state version. It is not Reporting/workflow authority. The provider receives only this bearer and four MCP business tools. Issuer/verifier are Word-specific, no generic auth platform.

One asynchronous MCP authorizer verifies credential, reads current task/input/fence, recovers registered session/context and verified source identity on every call. No DB lock is held for the model run. Existing NativeWordAITools implements exactly context/read/search/propose; full-read gate and single registration remain. Final content must exactly equal actual tool registration; no parsing prose as calls. Candidate commit uses existing immutable receipt CAS; local cancellation and durable task cancellation invalidate late publication. Credentials cannot authorize accept/save or access other files.

Coordinated completion uses versioned finish pointer to receipt and current durable run outcome. Recovery may reuse receipt without provider; never relabel provider error as provider success. COMPLETED means candidate complete, never saved. Registration into NativeAIService accepts only task reference, currently valid editor session and current base; loads completed receipt internally, rebuilds actual source/context/snapshot, previews candidate, rechecks current authority after awaits and registers stable task+candidate job id. No raw proposal registration. Existing accept_edit returns combined draft after explicit user action; existing save persists and independent readback proves selected paragraph change/control paragraphs preserved. New session used for acceptance need not keep executor lease alive.

## Entry and state
Proposed optional Word task dispatcher on existing start/status/events/cancel-request/cancel/accept service/route seam, default disabled and no app default wiring. Start supplies internal registered-session hash from authenticated cookie server-side, never payload. Task ref mapping is server-owned. Existing NativeAIService jobs remain UI projections only; durable task/receipt is completion authority. No parallel generic lifecycle state machine. Fail-closed selected backend cannot silently use ordinary Agno.

## Verification and non-goals
TDD credentials forgery/audience/scope/epoch/expiry tests, actual FastMCP four-tool calls, real PG current-fence/cancel/late output/recovery and receipt-final mismatch, actual synthetic DOCX scope/source/snapshot changes, current start/status/explicit accept/save and independent DOCX readback. No production business secrets, host paths or real provider until isolation verified; synthetic transport is explicitly reported as synthetic provider. Stage is jointly reviewed, no micro-PRs.

Remaining revocation races between independent services are not linearizable; final receipt CAS is authority, and acceptance revalidates a fresh editor grant/current draft. Generic completed cancel remains a no-op; UI discard does not revoke completed saved files. Deployment/worker/credential provisioning and real Codex execution are unverified and disabled.
