# 补证提速实施计划

日期：2026-10-27

状态：主体实现和定向故障注入已完成，生产端到端验收仍未完成；功能开关默认开启，显式设为 `false` 时回退到原 Python 路径。

## 目标与方案

在现有 AgentOS 服务内增加标准补证计算路径，尽量让常见、定义明确的计算由服务端直接完成；标准路径不生成或运行 Python 脚本。遇到首期不支持的计算时，仍使用补证脚本，但允许其自由组织函数、循环、分支和算法，不再要求线性写法或逐条遵循 planner 给出的实现步骤。

这里的“自由”指算法实现自由，不代表数据或运行权限无限制：脚本仍只能读取当前分析已授权的数据、写入签发的输出路径，并受现有执行时间和产物身份校验约束。补证目标、数据授权和最终证据契约不放开。

首期只要标准计算请求全部受支持，就走服务端；只要有一项不受支持，则该分析项整组走 Python 兜底。这样避免同一分析项混合两种执行回执，也避免为了混合计算扩展追溯结构。服务端结果和脚本结果最终进入同一证据校验、登记和下游读取流程。

## 实施阶段

### 1. 确定标准计算边界

- [x] 从 `deterministic_analysis.py` 提取窄接口，复用 CSV 原文读取、已确认范围过滤、完整分组精确求和、冻结粒度的日历期间解析与对账容差。指标聚合、单位、时间可加性及累计策略继续以冻结父事实为准，不在标准执行器重新推断。首期支持授权 CSV、同一 dataset/measure/period field、明确登记时间可加的 `sum`、非累计指标及完整冻结期间明细；单位换算、时点/累计指标、跨 dataset 对比和语义未确认的请求回退 Python。

## 接口与兼容约束

- 补证路由是内部结构化决策，不扩大模型可访问数据范围，也不改变用户侧报告接口。
- 服务端标准请求必须显式绑定已授权的 dataset、字段、分组维度和期间参数；不执行自由文本 SQL、Python `eval` 或未授权字段推断。
- `SupplementalEvidence` 是两种执行方式共用的最终输出契约；服务端不直接绕过 validator 写入已验收状态。
- `ComputationRecordV1` 继续使用现有格式版本；利用已有可选 `scriptFileResourceId` 表达服务端执行，不为服务端路径伪造脚本文件。
- 本轮不做“单一分析项内服务器计算 + 脚本继续计算”的混合拼接。标准请求全支持才走服务端，否则该项完整走脚本，以维持单一可核验执行来源。
- 当前 CodeMode 为宿主机执行适配，提示词和 AST/路径检查不能表述为操作系统级沙箱。此次算法自由度调整不授权开放任意网络、环境变量、数据库或子进程访问。

## 假设与默认选择

- “服务器端工具”指当前 AgentOS 服务内的分析计算能力，不另建 HTTP 计算微服务；用户已选择此方向。
- “无约束补证脚本”指算法实现自由，授权数据、文件身份和执行边界仍受控；用户已选择此方向。
- 首期优先减少模型写码、试跑和修复的往返次数，不假设 Python 数值计算本身是主要瓶颈。
- 首期只支持能用明确结构化参数表达、且能在限定支持边界内复现父事实期间与 scope 语义的标准需求；复杂需求维持现有 Python 兜底。
- 本计划记录的服务端实现仍处于未提交工作区；PR 142 自身只包含本计划文档。阶段 5 的真实 AgentOS 任务已终结并生成可下载产物，但正文验收有 24 条未修正提示，且未观察到标准补证路径命中；生产端到端对照验收尚未完成，不能据本地微基准宣称生产提速。

### 共享确定性语义的补齐与回归（2026-10-27）
