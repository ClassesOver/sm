# 补证提速实施计划

日期：2026-10-27

状态：待实施。本文记录已确认的方案与验收要求，不表示功能已经实现或测试通过。

## 目标与方案

在现有 AgentOS 服务内增加标准补证计算路径，尽量让常见、定义明确的计算由服务端直接完成；标准路径不生成或运行 Python 脚本。遇到首期不支持的计算时，仍使用补证脚本，但允许其自由组织函数、循环、分支和算法，不再要求线性写法或逐条遵循 planner 给出的实现步骤。

这里的“自由”指算法实现自由，不代表数据或运行权限无限制：脚本仍只能读取当前分析已授权的数据、写入签发的输出路径，并受现有执行时间和产物身份校验约束。补证目标、数据授权和最终证据契约不放开。

首期只要标准计算请求全部受支持，就走服务端；只要有一项不受支持，则该分析项整组走 Python 兜底。这样避免同一分析项混合两种执行回执，也避免为了混合计算扩展追溯结构。服务端结果和脚本结果最终进入同一证据校验、登记和下游读取流程。

## 实施阶段

### 1. 确定标准计算边界

- [ ] 复用 `smart_reporting/reporting/hospital_operation/deterministic_analysis.py` 已有的 CSV 读取、字段语义、单位、期间对齐、时点/累计规则、完整分组和对账逻辑；将需要复用的逻辑提取成窄接口，不另建通用计算引擎或自然语言表达式执行器。
- [ ] 首期服务端支持两类标准补证：单一授权维度的完整分组汇总（含排名、占比和与父指标总额核对）；按明确期间角色和粒度对齐的变化比较（含变化额、变化率及可比较范围内的贡献计算）。
- [ ] 比率、统计模型、复杂归因以及不能从结构化字段和参数明确描述的需求不进入首期服务端能力，统一交给 Python 路径。
- [ ] 在现有补证决策结构中增加可选的结构化执行路由和标准计算参数。计算目标只能使用当前分析授权的 dataset、字段、维度和期间配置。结构不完整、字段越权或参数语义不匹配时，不尝试猜测或自动改写，转入 Python 兜底并记录原因；回退仍须通过现有授权校验，不得执行越权请求。
- [ ] 保持 `facts_cover_analysis` 的现有跳过规则；证据已覆盖时不启动 planner、工具或脚本。

阶段验收：标准计算能力有明确支持范围；可支持、不可支持和越权请求均有定向用例，且不能通过回退扩大授权。

### 2. 增加服务端标准计算执行器

- [ ] 在 reporting 分析运行时内实现一个服务端执行入口，由固定 Workflow 根据结构化路由调用，不增加独立 HTTP 服务或网络跳转，也不再发起一次模型工具选择调用。
- [ ] 输入为已授权数据身份及内容、结构化标准计算参数和当前冻结分析事实；输出为 `SupplementalEvidence` 可接受的 findings、reconciliations 和 warnings。
- [ ] 对已登记业务语义、单位、缺失值、期间匹配和分组完整性沿用现有实现；缺失对照期间、不匹配分组、不可比较单位或无法闭合的对账应保留可用事实并产生软告警，不以猜测补零或终止工作流处理。
- [ ] 由服务端将结果写入现有签发的 evidence 路径，再通过统一 validator 校验。无 findings、超出体积上限或机器结构非法按结构/执行失败处理；业务对账失败仍是软告警。
- [ ] 使用项目现有 Agno Workflow/Function 组合方式与 loguru 日志，不新增调度框架或通用算子 DSL。

阶段验收：标准路径无需启动代码生成器即可产出通过机器结构校验的 evidence；业务对账失败能保留结果和具体告警。

### 3. 放开补证脚本的算法表达

- [ ] 更新补证脚本的任务说明和仅分析任务适用的源码预检：删除“一次线性数据流”“条件分支前初始化变量”等实现风格约束，也不要求脚本逐字照抄 planner 的每个 calculation 描述。
- [ ] 保留源码可解析、输出身份可验证、仅读取签发 Dataset 路径、仅写入签发 evidence 路径、证据 JSON 契约和非有限数值检查。自由算法不得绕过数据授权或工作区边界。
- [ ] 不改通用 Coding Toolkit 的共享路径策略、执行回执语义或可视化脚本约束；Matplotlib 静态图要求不变，且不新增 Plotly 能力。
- [ ] 为不可支持或结构不合法的服务端请求设置明确回退条件：执行器未开始写结果时可直接切换脚本；若服务端执行已经写出文件，则先清理或隔离该次未登记文件，再运行脚本，禁止复用其残留内容。
- [ ] 保持 `write_script`、`run` 在 provider wire 层的原生 free-form custom tool 协议，不降级为 JSON function tool，不执行 assistant 正文中的代码或伪工具调用。多调用响应先整批校验，再按 provider 顺序委托 Agno 执行；前序失败或成功提交后，其余调用仅补齐匹配身份的未执行回执。

阶段验收：函数、循环和多分支脚本可执行和提交；路径越权、输出身份变化及非法 evidence 仍被正确拒绝；可视化与工具协议回归不退化。

### 4. 统一产物身份与追溯

- [ ] 在分析工作流状态中增加服务端计算回执，与现有脚本回执分开建模；服务端回执记录执行 ID、方法及版本、授权输入文件身份和 evidence 输出文件身份，不伪造 Python 源文件身份。
- [ ] 扩展现有服务端计算记录构造逻辑：服务端计算的 `scriptFileResourceId` 允许为空；以 `method`、`methodVersion`、参数、输入数据集身份和输出 evidence 引用表示计算来源；`verification` 仍为 `not_checked`，不把运行成功表述成独立数值复核通过。
- [ ] 将可选的服务端回执/计算记录纳入 durable completion 和恢复校验，保证重启后重放时身份与首次提交一致。旧 checkpoint 缺少新字段时按无服务端计算记录读取。
- [ ] 服务端路径、Python 路径最终都执行同一套实际文件 hash/身份核验、supplemental validator、指标范围检查、证据登记和下游索引构建；任何身份不匹配都丢弃对应结果，不签发伪造追溯。
- [ ] 保持发布、PDF/Word 下载和工作流完成的非阻断契约：语义校验只软告警；报告产物已生成且实际身份可读取时，补证验收或追溯问题不得阻止下载签发，应保留失败状态并返回具体原因。

阶段验收：服务端和脚本产物均可追溯、恢复及幂等重放；旧记录兼容；身份漂移仅拒绝对应数据，不能阻断已核验报告产物的下载签发。

### 5. 灰度、观测与回退

- [ ] 增加服务端路径功能开关，默认关闭；按分析项记录路由选择、命中/回退原因、各阶段耗时、脚本生成与修复次数、证据大小、结构校验状态及告警数。日志不包含 CSV 内容或敏感业务明细。
- [ ] 灰度期间关闭功能开关即可回到当前 Python 补证路径，无需迁移已冻结 evidence；新旧 durable completion 均可恢复。
- [ ] 用相同冻结输入、相同模型和运行配置对比当前基线与开启后的端到端时延；报告样本数、P50/P95、服务端命中率、回退率、证据验收率和覆盖质量，不预设或承诺固定提速倍数。
- [ ] 真实 AgentOS 验证遵守项目 `smart-reporting-real-os-test` 规范：沿用实际环境设置和原生后台运行接口，默认只提交一次，不自动重提。

阶段验收：开关可回退，观测可解释每项计算路径与耗时；满足性能和质量验收后再逐步启用。

## 接口与兼容约束

- 补证路由是内部结构化决策，不扩大模型可访问数据范围，也不改变用户侧报告接口。
- 服务端标准请求必须显式绑定已授权的 dataset、字段、分组维度和期间参数；不执行自由文本 SQL、Python `eval` 或未授权字段推断。
- `SupplementalEvidence` 是两种执行方式共用的最终输出契约；服务端不直接绕过 validator 写入已验收状态。
- `ComputationRecordV1` 继续使用现有格式版本；利用已有可选 `scriptFileResourceId` 表达服务端执行，不为服务端路径伪造脚本文件。
- 本轮不做“单一分析项内服务器计算 + 脚本继续计算”的混合拼接。标准请求全支持才走服务端，否则该项完整走脚本，以维持单一可核验执行来源。
- 当前 CodeMode 为宿主机执行适配，提示词和 AST/路径检查不能表述为操作系统级沙箱。此次算法自由度调整不授权开放任意网络、环境变量、数据库或子进程访问。

## 测试与验收

| 范围 | 必须覆盖的行为 | 验收标准 |
| --- | --- | --- |
| 服务端计算 | 完整分组而非 top/bottom 子集、分组总和闭合、排名与占比、零分母、空值、不匹配分组、期间粒度对齐、缺少可比期间、单位不可换算、时点和累计快照 | 与冻结语义一致；不可计算值保留空值和原因；业务差异仅软告警 |
| 路由 | 全部需求受支持、任一需求不受支持、越权 dataset/字段、执行异常、文件身份变化 | 标准路径不启动代码生成；不支持时整组回退；回退不扩大授权、不使用旧文件 |
| 自由脚本 | 函数封装、循环、多分支、未授权路径、额外输出、非法 JSON、NaN/Infinity | 合法算法表达可提交；结构与身份校验继续生效；可视化行为不变 |
| 工具协议 | 同响应中混合多个 custom/function 调用、失败后停止、提交后停止、结果回放 | 顺序执行与回执身份符合 AGENTS.md 协议契约 |
| 证据与追溯 | 统一 validator、无脚本的服务端记录、方法版本和输入输出身份、旧记录恢复、新记录幂等重放、身份漂移 | 不伪造执行来源或复核状态；漂移结果不登记 |
| 发布与下载 | 验收失败、门禁异常、追溯故障、完成消息原因 | 已生成且实际身份可读取的 PDF/Word 照常签发，明确返回失败和告警 |
| 性能 | 相同冻结输入、模型和配置下的端到端对比 | 服务端命中任务减少生成/修复环节并有可测提速；证据验收率和必要事实覆盖不退化 |

执行测试时先按改动范围运行 deterministic、supplemental evidence、analysis workflow/recovery、trace computation 和 section evidence 的定向测试。发布链路有改动时，运行 AGENTS.md 列出的非阻断回归契约；新增签发阶段可失败步骤必须登记到 HTTP publication 故障注入用例，新签发函数必须登记到 `_SIGNING_CHAIN`。不重复完整测试套件。

性能验证需报告实际样本量和分布；样本不足时不得将 P95 或提速幅度作为稳定结论。未满足性能与质量条件时保持服务端功能开关关闭，根据回退原因调整首期支持边界。

## 假设与默认选择

- “服务器端工具”指当前 AgentOS 服务内的分析计算能力，不另建 HTTP 计算微服务；用户已选择此方向。
- “无约束补证脚本”指算法实现自由，授权数据、文件身份和执行边界仍受控；用户已选择此方向。
- 首期优先减少模型写码、试跑和修复的往返次数，不假设 Python 数值计算本身是主要瓶颈。
- 首期只支持能用明确结构化参数表达、且能复用现有语义和期间逻辑的标准需求；复杂需求维持现有 Python 兜底。
- 本文中的阶段勾选项为后续实施清单，全部尚未执行；实施时保留工作区中既有的无关改动。
