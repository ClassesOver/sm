# XLSX 透视与保护并行实施计划

**目标：** 接通高级透视筛选和允许编辑区域的本地入口、操作协议、保存回读；对标准 OOXML 尚不支持的能力明确说明。

**已确认范围：** 用户要求第 4、5、6 项同时推进。基于当前工作区的未提交实现继续开发，不覆盖其他改动、不提交、不重复完整测试。

**架构：** 复用现有 XLSX 引擎、操作日志和全文件预演。透视配置/筛选/保护各自维护独立模块，主视图负责获取最新文件、锁定编辑、应用预演结果、草稿及撤销恢复。切片器与时间线入口只承诺实际落盘的筛选状态，不宣称生成 Excel 原生控件。

## 并行任务

- [x] 高级透视：扩展 `workbook-pivot.ts` 和对话框，连接引擎已有分组、公式、筛选；补齐可安全实现的列轴多值、共享缓存隔离和表来源刷新。先写行为回归，验证实际结果及 ZIP/XML 回读。不能保真的导入结构继续只读。
- [x] 切片器/时间线：新增 `workbook-pivot-filters` 计划和对话框，选择成员或日期区间，复用高级透视计划；测试过滤结果、无效日期、保存重开和原生控件能力边界。
- [x] 允许编辑区域：扩展标准 `protectedRanges` 读写，新增管理对话框和计划；保护下仅允许范围内的值/公式修改，禁止越界和格式变更。测试重开、受密码保护范围保留及命令/保存双端校验。
- [x] 主视图集成：接通 Ribbon、新操作的浏览器/Node/Python 协议；复用透视事务与历史恢复，失败时保持原草稿和网格。增加真实主视图保护编辑/保存回归。

## 验收边界

1. 会话操作、引擎私有扩展、Excel 标准控件持久化分别描述。
2. 保存必须是实际完整 XLSX 文件，重开后读取真实筛选/范围/透视结果。
3. 不解除共享缓存、带密码区域等保护性限制，除非有验证过的隔离或保真实现。
4. 不修改报告发布验收与下载签发链路。
