# 批准依赖工作流状态稳定读取计划

**目标：** 把已实际核验的Reporting运行/状态依赖稳定持有到偏好版本提交，不把同机来源锁称为跨状态库保证。

**方案：** 既有原生SQL仓储记录当前任务四个读取入口的完整行见证；缺失/重复漂移拒用。核验完成后按表/id顺序FOR SHARE并精确比较，同引擎复用管理事务连接，独立引擎在管理事务前持来源事务。所有锁随上下文释放，过期、撤权、合同/材料/文件与CAS检查保留。不新建调度、状态平台或分布式写事务。

**约束：** 当前工作区；现存文件修改前完整保存；不读.env，不改生产合同或下载链路；不重复完整测试。异步任务继承的上下文不能把另一任务的读取算父任务证明。不支持稳定读取的仓储应明确拒绝正式apply。

1. 真实SQL状态复现核验后状态/运行被更新仍提交的竞态；先写失败测试。升级既有approved测试夹具为真实Reporting SQL状态，保留小合同/字段证据替身的边界。
2. 新增窄读取见证与原生仓储四读取入口接线；验证行变化、缺失、重复漂移、捕获隔离、排序及持锁，生产服务实际接通，禁止只留未消费能力。
3. apply捕获全部依赖并在版本事务提交前持稳定行锁；分别验证同引擎单连接池和分离状态引擎，提交前漂移、事务内并发更新/撤权、取消/回滚释放，不把只读证明称为跨库写事务。
4. 同模型只读复核、定向回归、源码/合同/旧归档身份核验及增量文档冻结。完整设计未证明前保持active/canApply=false。
