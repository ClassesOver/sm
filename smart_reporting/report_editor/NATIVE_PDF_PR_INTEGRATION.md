# PDF PR 隔离集成说明

2026-11-11；发布基线 `9d90d2d022c53631f01cb36f5d799034661dde99`；分支 `feat/pdf-genoffice-alignment-20261111`。

本 PR 收录本会话累积的 PDF 文字编辑、Office/文本转换、表单设计及必要的阅读、审阅、派生产物交付能力。OCR 不在本次交付范围。独立 Word、Excel、管理端功能和 DOCX 引擎目录迁移不纳入本 PR；PDF 转换沿用基线 `slides_engine/packages/docx-engine`、PPTX 和 XLSX 引擎。

## 验证证据的适用范围

`NATIVE_PDF_*_ACCEPTANCE.md` 记录原开发树各批次的分层证据与限制，不代表本 PR 的隔离组合重新通过浏览器或宿主验收。原开发树的 49 个前端、192 个引擎清单文件、955 个 bundle inputs、本地及固定上游哈希已重新核对一致。隔离组合采用基线共享引擎，构建输入和输出身份随之改变，不能沿用原运行包的精确身份结论。

初始隔离验证以 `9f2c4944d96ccab0671026af7f8c38ffc293b3c0` 为基线。发布前目标分支合入 XLSX PR #213，PDF 分支已更新至上述发布基线；共享 API 保留双方增量，Vite 完整保留新基线配置并仅增加六条 PDF/共享叶模块分块规则。原基线证据保留，新基线结果如下：

- 原隔离组合的 42 项定向测试通过；更新基线后，受影响的 native-api 八项和 serializer 两项共 10/10 通过，最终 Vite 构建通过。最终本地依赖指向隔离 XLSX 基线，排除中间构建对原开发树的依赖。
- PDF 相关分块均通过发布基线预算，本 PR 未提高限额；最终 main 为 220,568 字节。
- 新基线全局分块预算仍未通过两项：`workbook-engine` 为 563,549 字节（阈值 405,504），`workbook-icons` 为 280,818 字节（阈值 280,576）。未做独立的 base-only 构建，不能将失败归因为既有问题；不沿用旧组合的 553.8 KiB 结论。
- PDF bundle 和运行包构建通过，845 个构建输入，无隔离树外的 Office 源码输入；CLI SHA-256 为 `d0328bb6b5eabcefcbe78c4f3fb06ed1ebcb347e4ad258c4f6c52b631b56b247`。
- 新发布基线的六个转换测试文件共 30 个目标用例通过。复杂 fixture 的文字断言改为同段落内的可见文字，允许合法链接 run 边界，保留显式换行和原有内容、字体、表格与几何要求。
- 187 项引擎 LOCAL 清单、converter 本地哈希与来源清单一致。固定上游哈希保持上游身份，不能以本地适配后的哈希替代。
- 后端按非阻断契约、HTTP 故障注入、启动接线和运行包范围进行专项验证；共享签发修复后，AGENTS 登记的 11 条契约展开为 69 项通过，另 7 项原生 Word 发布专项通过。新增双重复核 helper 故障及真实文件缺失/篡改边界均通过；提取链路另覆盖回执、写后和复核异常。测试分批收尾，不把重复参数累计为不同能力。

本次未重复完整项目测试，也未在新组合上重跑完整浏览器、Writer、Calc 或 Impress 验收。构建和专项成功不等于完整视觉或业务验收通过。

## 发布与已知限制

实际文件身份可核验时，回执、登记或后置验收异常应保留下载链接，同时返回具体告警；实际文件缺失或身份不匹配时不签发对应产物。所有新派生保存仍保留 `validation.ok=false` 或明确的待核状态，不能据此标记业务验收通过。

整体 PDF 对齐、复杂版式和字体完整保真仍未完成；XFA、任意复杂多 Widget、签名与保护来源等限制继续以 `NATIVE_PDF_ALIGNMENT_STATUS.md` 为准。PDF 入口未直接注册独立 Word CJK 字体资产，不将原开发树字体渲染证据泛化到本 PR。全局包预算待处理，因此当前以草稿 PR 提交审阅。

本地原始日志与冻结证据保留在 `/tmp/pdf-pr-*`（部分大产物以同名路径链接至 `/dev/shm`），不提交生成的运行包、构建输出或依赖目录。PDF fixture 与字体版权文本保持原始字节；差异空白检查排除这些原样证据文件。
