## Source implementation already inherited (avoid false positives)

`docx-main.tsx:374` spreads **all** imported `editorExtensions` (with nested-table/row substitutions), then adds native extensions and Guard. Source presence of a vendored file alone is insufficient, but actual extension registration here is meaningful. `WordEditorShortcuts`, `AutoCorrectExtension`, `MultiSelect`, keyboard list promotion and underlying typography behaviors must be checked at registration/persistence boundaries before called absent. Conversely a copied React dialog/utility without a native caller does not prove parity.

The expanded shared `packages/ui/src/shape-gallery.tsx` is already vendored; local `docx-insert-object-params.ts` explicitly cites the canonical shape IDs. Do not call the shape gallery missing simply because it is a shared package. There is no Docs `RightPanel.tsx` in the fetched tree; do not import a slides-only feature family into Word gaps. Other shared AI panel details are owned by the AI auditor.

## Honest exhaustiveness boundary

An exhaustive fixed-source audit can mean: enumerate **every callable user surface** in this pinned Docs app (ribbon buttons, galleries/options, dialog tabs/fields, context menus, menu-command IPC, keyboard handlers, pointer/drop/paste behaviors, status/navigation/comment/HF panes, command/control APIs), trace shared imported implementations, and record local reachability + editing/save round-trip limits for each. It does not mean all Microsoft Word versions/features or all ECMA-376/OOXML constructs. Rendering/parser preservation behavior is a separate dimension; presence in a DOCX parser is neither a callable command nor proof of editable save support. Static inspection establishes source gap evidence, not browser acceptance. Transitive package fetching must be reflected in final manifest/count, so the initial 441-file set is not the whole app's transitive closure. Desktop-only integration should be labeled host divergence, not silently mixed with document editing gaps.
