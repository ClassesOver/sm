## Additional boundaries and audit uncertainty

Source native archive opening and patching have finite entry/part/row/edit bounds documented above. The source's no-total-archive-limit comment is explicitly scoped to archive layer; metadata/shared strings/styles can still occupy memory, encrypted CFB opens read into memory, conversion builds full sheet XML strings, and patch/recovery paths can require large allocations. Neither architecture's real maximum workload or resource isolation has been benchmarked here.

Encrypted OOXML password open/save and `.xlsm` macro preservation appear in source `sheets-main.ts` (`decryptOoxml`, `encryptOoxml`, `macroEnabled`), encrypted open/password belongs to core, and macro preservation is explicitly owned by S13 below. Source `.xlsx` zero-byte open is specially converted into a blank workbook (`openEmptyXlsx`); local `native_office._content` rejects empty bytes. Root can track this as an additional narrow file-open difference if within native report attachment scope.
