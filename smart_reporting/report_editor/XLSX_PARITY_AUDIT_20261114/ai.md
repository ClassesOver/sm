## Findings that change older AI coverage claims

- Current `workbook_ai_tools.py:WorkbookAIToolkit.__init__` registers **11 of 13** source workbook tools: get_workbook_context/read_range/read_cells/read_formats/read_sheet_features/find_cells/aggregate_range/trace_precedents/trace_dependents/load_guide/propose_operations. Both formula trace tools are implemented now. Missing source workbook tools are select_range and create_document, which exceed candidate-edit authority.
- `workbook_ai_tools.py:_translate` supports source `add_chart` and `edit_chart` now, including real data ranges via `applyChartSource`. `WorkbookAIProposal` also permits native trusted chart format/deletion operations. Frontend `workbook-native-ai.ts:mountWorkbookNativeAI` help still incorrectly claims AI cannot create charts or change chart data; API/planner support and product copy disagree.
- There is a separate native XLSX **read-only** route, not merely an edit proposal prompt: `native_workbook_read_ai.py:NativeWorkbookReadTools` + `AgnoNativeWorkbookReadPlanner`, `native_office_read_tasks.py:NativeOfficeReadService`, registered by `app.py`. It provides 7 query tools with paging, scope-bound frozen values/formulas, citation verification and coverage warnings, no writes.
- Native editing task/candidate storage is in-memory dictionaries plus asyncio tasks. Shared `task_execution` SQL repository/lease/recovery code exists but these workbook candidate and read services do **not** use it. Durable task recovery cannot be credited from repository infrastructure alone.
